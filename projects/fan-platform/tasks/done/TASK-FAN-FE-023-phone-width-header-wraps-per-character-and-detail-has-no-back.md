# Edge Cases

| 상황 | 기대 |
|---|---|
| 피드 → 상세 → 뒤로 | 피드, 스크롤 위치 유지 |
| `/artists/{id}` → 상세 → 뒤로 | `/artists/{id}` (피드 아님) |

# Failure Scenarios

1. **뒤로가기를 `<Link href="/">` 로 고정한다** → `/artists/{id}` 에서 온 방문자가 피드로 튕긴다. 시험이 href 만 보면 초록.
2. **무조건 `router.back()` / `history.back()`** → 공유 링크로 들어온 면접관이 «뒤로» 를 누르면 **빈 탭이나 이전 사이트**로 나간다.
3. **`document.referrer` 로만 판정한다** → 앱 안 이동은 referrer 를 안 바꾸므로 «직접 진입 후 앱 안 이동» 에서 오판한다(Edge 표 🔴 행).
4. **헤더를 클라이언트 컴포넌트로 바꾼다(햄버거 등)** → 서버에서 읽던 세션·알림 조회가 경계를 넘는다. `Header.tsx` 머리말의 «익명 방문은 게이트웨이 호출 0건» 성질이 흔들린다. 이 티켓은 **클래스만** 바꾼다.
5. **`useRouter` 를 뒤로가기에 쓴다** → 앱 라우터 컨텍스트가 없는 jsdom 에서 기존 페이지 시험(`public-pages.test.tsx`)이 `next/navigation` 모킹 없이 죽는다. `notFound` 도 같은 모듈이라 통째로 모킹하면 notFound 칸이 거짓이 된다.
6. **줄바꿈 금지만 넣고 줄 배치를 안 정한다** → 항목이 안 쪼개지는 대신 문서가 **가로로 넘친다**(AC-1 넘침 칸이 무는 자리).

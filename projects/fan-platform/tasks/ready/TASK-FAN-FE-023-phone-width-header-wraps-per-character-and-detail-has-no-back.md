# Acceptance Criteria

## AC-0 — 착수 전 실측

- [ ] 위 표를 `main` 의 라이브에서 다시 잰다(같은 스크립트 · 같은 너비). 원인 줄(`<nav className=…>`)이 그대로인지 본다.

## AC-1 — 헤더: 항목이 쪼개지지 않는다

- [ ] 360 · 400px 에서 헤더의 **모든 링크·버튼이 1줄**이다(텍스트 줄 수로 잰다 — 높이만 보면 두 줄 배치와 글자 줄바꿈이 안 갈린다).
- [ ] 휴대폰 너비 배치: 첫 줄 = 로고 + 오른쪽 동작(익명은 `로그인`), 둘째 줄 = `피드` · `아티스트` · `멤버십`. 🔵 줄 두 개는 **의도한 배치**이고 결함이 아니다.
- [ ] 문서 가로 넘침 없음(`scrollWidth ≤ innerWidth`) — 360 · 400px.
- [ ] 🔴 **대조군**: 768 · 1280px 은 지금과 같다 — 한 줄 · 헤더 높이 57px · 항목 순서(로고 → 피드 → 아티스트 → 멤버십 → 오른쪽 동작).
- [ ] 🔴 로그인 상태 헤더(항목 다섯 추가)도 360px 에서 항목이 쪼개지지 않는다. 라이브로 못 재므로 **무엇으로 쟀는지와 그 한계**를 Verification 에 적는다(재현본이면 «재현본» 이라고).

## AC-2 — 상세: 온 곳으로 돌아간다

- [ ] `/posts/{id}` 네 갈래(회원 성공 · 회원 `MEMBERSHIP_REQUIRED` · 공개 열림 · 공개 잠김) **전부** 본문 위에 «← 뒤로» 가 있다.
- [ ] 🔴🔴 **앱 안에서 왔으면 브라우저 뒤로**(`history.back()`)다 — `/artists/{id}` 에서 들어왔으면 `/artists/{id}` 로, 피드에서 왔으면 피드로 돌아간다(스크롤 위치도 브라우저가 되살린다). 고정 링크 `/` 는 **안 된다**(Failure 1).
- [ ] 🔴🔴 **앱 안 이력이 없으면**(공유 링크로 새 탭 직접 진입) 사이트 밖으로 나가지 않고 `/` 로 간다(Failure 2).
- [ ] 진짜 `<a href="/">` 다 — JS 가 없거나 ⌘/Ctrl/Shift/가운데 클릭이면 브라우저 기본 동작(새 탭에 피드)을 가로채지 않는다.
- [ ] 🔴 익명 상세 렌더의 **요청 0건**(`public-pages.test.tsx` 의 `fetch` 스파이)이 계속 초록이다.

## AC-3 — 시험

- [ ] 뒤로가기 판정: ⓐ 앱 안 이동 이력 있음 → `history.back()` 호출 · 기본 이동 막음 ⓑ 이력 없음 → `history.back()` **안 부름** · `href="/"` 로 이동 ⓒ 수정키 클릭 → 가로채지 않음. 🔵 ⓐⓑ 는 서로의 **대조군**이다 — 한쪽만 있으면 «항상 back» 이나 «항상 /» 가 초록으로 통과한다.
- [ ] 상세 네 갈래 각각에 뒤로가기가 **정확히 하나**.
- [ ] 🔵 jsdom 은 줄바꿈·레이아웃을 못 잰다 ⇒ AC-1 은 **실제 브라우저**로 잰다(AC-4).

# Edge Cases

| 상황 | 기대 |
|---|---|
| 피드 → 상세 → 뒤로 | 피드, 스크롤 위치 유지 |
| `/artists/{id}` → 상세 → 뒤로 | `/artists/{id}` (피드 아님) |
| 🔴 `/artists/{id}` 로 **직접 진입** → 카드 → 상세 → 뒤로 | `/artists/{id}` — 🔴 Next 의 화면 안 이동은 `document.referrer` 를 **안 바꾼다**(referrer 는 빈 채) ⇒ referrer 만 보면 `/` 로 잘못 간다 |
| 공유 링크로 상세 **직접 진입**(새 탭) → 뒤로 | `/` |
| 다른 사이트(검색 결과 등)에서 상세로 들어옴 → 뒤로 | `/` — 이전 사이트로 나가지 않는다 |
| 상세 → 상세(알림 등 연속) → 뒤로 | 직전 상세 |
| ⌘/Ctrl 클릭 · 가운데 클릭 | 새 탭에 `/` — 가로채지 않는다 |
| 로그인 헤더, 360px | 항목 쪼개짐 없음 · 동작 줄이 넘치면 **항목 단위**로 줄바꿈 |

# Failure Scenarios

1. **뒤로가기를 `<Link href="/">` 로 고정한다** → `/artists/{id}` 에서 온 방문자가 피드로 튕긴다. 시험이 href 만 보면 초록.
2. **무조건 `router.back()` / `history.back()`** → 공유 링크로 들어온 면접관이 «뒤로» 를 누르면 **빈 탭이나 이전 사이트**로 나간다.
3. **`document.referrer` 로만 판정한다** → 앱 안 이동은 referrer 를 안 바꾸므로 «직접 진입 후 앱 안 이동» 에서 오판한다(Edge 표 🔴 행).
4. **헤더를 클라이언트 컴포넌트로 바꾼다(햄버거 등)** → 서버에서 읽던 세션·알림 조회가 경계를 넘는다. `Header.tsx` 머리말의 «익명 방문은 게이트웨이 호출 0건» 성질이 흔들린다. 이 티켓은 **클래스만** 바꾼다.
5. **`useRouter` 를 뒤로가기에 쓴다** → 앱 라우터 컨텍스트가 없는 jsdom 에서 기존 페이지 시험(`public-pages.test.tsx`)이 `next/navigation` 모킹 없이 죽는다. `notFound` 도 같은 모듈이라 통째로 모킹하면 notFound 칸이 거짓이 된다.
6. **줄바꿈 금지만 넣고 줄 배치를 안 정한다** → 항목이 안 쪼개지는 대신 문서가 **가로로 넘친다**(AC-1 넘침 칸이 무는 자리).

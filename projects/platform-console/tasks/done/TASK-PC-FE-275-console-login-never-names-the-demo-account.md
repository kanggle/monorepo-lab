# Goal

`console-web` 의 `/login` 은 **콘솔의 유일한 익명 표면**인데, 데모 배포에서 그 화면이
`demo@demo.com` / `Demo1234!` 를 **한 글자도 말하지 않는다**. 이 티켓이 끝나면 데모
배포의 `/login` 이 계정과 「테넌트를 `demo-corp` 로 고르라」는 다음 한 걸음을 그 자리에서
말하고, 그 리터럴이 시드가 실제로 쓰는 값과 **CI 에서 대조**된다. 데모가 아닌 배포
(로컬 · CI)에서는 **0바이트** 그대로다.

## 이 티켓이 왜 지금 생겼는가 — 소유자 관측 (2026-09-07)

소유자가 콘솔에서 다음 화면을 만나고 물었다: *"면접관들이 콘솔에서 조직을 만들어야지만
테스트를 할 수 있도록 되어 있어?"*

> **조직 만들기** — 로그인은 완료됐지만 아직 소속된 워크스페이스가 없습니다. …
> 조직 ID `acme-corp` …

**답은 「아니오」다.** `/onboarding` 은 필수 관문이 아니라 셀프서비스 온보딩 데모이고
(`ADR-MONO-044` §3.4 / `TASK-PC-FE-182`), 도달 조건은 **테넌트 assignment 가 0인 계정**
하나뿐이다(`app/api/auth/callback/route.ts:187-191` — operator-exchange 가
`not_provisioned` 이면 재로그인 대신 여기로 보낸다). 시드된 `demo@demo.com` 은
`demo-corp`(5도메인 구독) + `ecommerce` 두 테넌트의 운영자라 이 화면을 **지나가지 않는다**
(`R__05_seed_demo_corp_tenant_and_consumer_accounts.sql` · `R__seed_demo_operator.sql`,
둘 다 `migration-dev` 이고 데모 스택은 기본 프로파일이라 로드된다 —
`admin-service/application.yml:15-18`).

⇒ **결함은 온보딩 화면이 아니라 그 앞이다.** 계정을 모르는 방문자만 그 화면에 도달하고,
계정을 모르게 만드는 것은 `/login` 이 아무 말도 안 한다는 사실이다.

## 🔴 이것은 이미 한 번 고쳐진 결함의 **낙오한 형제**다

`TASK-MONO-561` 이 **같은 결함을 런처에서** 고쳤다. 그 블록의 주석이 결함을 스스로
이렇게 적어 뒀다(`infra/demo/aws/site/index.html:170-176`):

> 이 블록이 없어서 방문자가 못 들어갔다. 로그인 화면은 나오는데 계정을 모르니
> "회원가입" 을 누르게 되고, 그 경로는 콘솔 클라이언트에서 **구조적으로 불가능**하며
> (`TASK-BE-581`) 실패 메시지마저 틀렸다(`TASK-BE-580`). 두 결함은 방문자가 이 구멍을
> 메우려다 밟은 것이다.

**소유자가 오늘 본 화면은 그 문장의 2026-09-07 판이다.** `TASK-PC-FE-182` 가 가입 경로를
「구조적으로 불가능」에서 「가능하지만 빈 조직」으로 바꿨으므로 증상만 바뀌었다:
`TASK-BE-580` 의 틀린 404 메시지 대신, **잘 도는 온보딩 화면**이 방문자를 맞는다. 더
조용해졌을 뿐 방문자가 데모를 못 보는 것은 같다 — 그 길로 만든 조직은 화면이 스스로
말하듯 **도메인 구독 0 · 데이터 0** 이라, 구독을 켜도 운영 화면이 전부 비어 있다.

## 🔴🔴 런처에 적혀 있으니 됐다 — 가 성립하지 않는 이유는 **측정 가능**하다

런처의 콘솔 링크는 `target="_blank"` 다(`index.html:162`). 즉 방문자는 **계정 카드가
있는 탭을 떠나** 새 탭의 로그인 화면에 도착한다. 자격증명은 **다른 탭에 있다.** 런처를
거친 방문자에게조차 「이 화면에 계정이 없다」가 참이고, 북마크·공유 링크로 콘솔 URL
(`https://console.hubwang.com/`)에 직접 오는 경로는 그보다 더 노골적이다.

🔵 그리고 이 자리는 이미 **데모 전용 문구를 렌더하는 자리**다 — `DemoBackendNotice` 가
같은 페이지에 붙어 있고(`login/page.tsx:63`), 그 위젯의 헤더가 왜 콘솔만 로그인에
다는지를 이미 논증해 뒀다(*"page.tsx 67개 중 익명으로 닿는 것이 `/login` 하나"*).
새 자리를 만드는 것이 아니라 **그 자리에 빠져 있는 문장 하나를 채우는 것**이다.

# Scope

## In Scope

- `console-web` `/login` 에 **데모 전용** 계정 힌트 블록 추가(서버 컴포넌트).
  렌더 조건은 `resolveDemoBackendState() !== 'not-demo'`.
- 블록 내용: 이메일 · 비밀번호 + **로그인 후 테넌트를 `demo-corp` 로 고르라**는 한 줄
  (런처 힌트와 같은 사실 — 계정만 알고 테넌트를 안 고르면 빈 화면 + 403 을 본다).
- `infra/demo/verify-demo-wrapper.sh` 의 **z11 셀 확장**: 지금 2자(런처 HTML ↔
  `seed/lib.sh`) 대조를 **3자**로 늘려 이 위젯의 리터럴을 포함시킨다. 권위는 지금처럼
  `lib.sh` 다(그 값은 부팅마다 실제 로그인에 쓰인다).
- 유닛 테스트 3케이스(`not-demo` → null / `running` → 렌더 / `unavailable` → 렌더).

## Out of Scope

- `/onboarding` 화면의 변경 · 제거 · 게이팅. **그 경로는 결함이 아니다** — `ADR-MONO-044`
  §3.4 가 의도한 셀프서비스 데모이고, 이 티켓은 그 화면에 **잘못 도착하는 것**만 고친다.
- 자격증명 프리필 · 자동 로그인 · 원클릭 데모 로그인 버튼. IAM OIDC Auth Code + PKCE
  왕복을 건드리는 일이며 별개 결정이다(필요하면 별도 티켓).
- 형제 앱(`web-store` · `fan-platform-web`)의 같은 블록. 그쪽 익명 표면은 로그인이 아니라
  카탈로그/피드라 **판단이 다르다**(`DemoBackendNotice` 가 fan 에서 `/login` 을 일부러
  비워 둔 것과 같은 이유). 별도 티켓 후보로만 남긴다.
- README · 워크스루의 자격증명 문구 변경(이미 정확하다).

# Edge Cases

- **`unavailable` 상태에서 두 블록이 같이 뜬다** — 의도한 것이다. 하나는 *왜 지금 로그인이
  안 되는가*, 다른 하나는 *켜지면 무엇으로 들어가는가* 를 말한다. 🔴 두 문장을 하나로
  합치지 마라 — 합치는 순간 둘 중 하나는 거짓이 된다(`DemoBackendNotice` 헤더의 같은 논증).
- **해석기가 `/status` 에 실패한 경우** — 해석기는 그때 「꺼짐」으로도 「켜짐」으로도
  번역하지 않는다. 이 블록의 술어는 「이 배포가 데모인가」이지 「백엔드가 사는가」가
  아니므로 그 경우에도 렌더된다. 그것이 옳다.
- **`DEMO_API_BASE` 가 없는 컨테이너 데모**(`demo-up.sh` 로 띄운 로컬) — `not-demo` 로
  판정되어 블록이 **안 뜬다**. 🔴 이것은 결함이 아니지만 **혼동의 씨앗**이다: 로컬에서
  눈으로 확인할 수 없다는 뜻이므로, AC-4 의 유닛 테스트가 그 자리를 대신한다.
- **비밀번호가 바뀌는 날** — 세 사본(런처 · `lib.sh` · 위젯)이 z11 로 묶이므로 하나만
  고치면 CI 가 RED 다. 🔵 그것이 이 AC-3 의 전부다.

# Failure Scenarios

- **가드를 3자로 늘리면서 술어가 「하나라도 같으면 통과」가 된다** — `break` / `head -1`
  은 존재 한정사다. 요구는 「**셋이 모두** 같다」이므로, 한 사본이 어긋났을 때 반드시
  RED 여야 한다. AC-3 의 주입 대조군을 **사본마다** 돌린다.
- **위젯이 `not-demo` 에서도 렌더된다** — 로컬 개발 화면과 CI 스냅샷에 데모 비밀번호가
  뜬다. AC-4 의 `null` 단언이 이 축의 유일한 방어다.
- **블록을 `(console)` 레이아웃에 단다** — 그 66개 화면은 이미 로그인한 사람이 본다.
  자리는 `/login` 하나다.
- **`resolveDemoBackendState()` 를 클라이언트 컴포넌트에서 부른다** — 판정이 비공개 env
  에 달려 있어 그 이름이 클라이언트 번들에 들어간다. 서버 컴포넌트를 유지한다.
- **z11 의 위젯 추출식이 산문에 걸린다** — 이 티켓의 본문과 위젯 주석에 `demo@demo.com` 이

# Goal

탭 다섯 개가 서로 비슷해 보여 무엇을 어디서 찾는지 헷갈린다. 원인 둘:

1. 「메뉴별 설명」과 「메뉴별 사용 절차」가 같은 권한 표 행에서 만들어지고, 절차 탭의 3·4단계(화면 내용 · 할 수 있는 조작)는 설명 카드의 반복이었다. 절차에만 있던 것은 «여는 곳» 과 «필요한 권한» 두 줄.
2. 「대표 업무 흐름」이 전역 가이드(여러 메뉴를 거치는 일의 순서)와 도메인 가이드(한 건이 거치는 상태)에서 다른 뜻으로 쓰였다.

탭마다 답하는 질문이 하나가 되게 한다.

| 탭 키 | 옛 이름 | 새 이름 | 답하는 질문 |
|---|---|---|---|
| overview | 도메인 전체 설명 | (그대로) | 이 도메인은 뭘 하는 곳? |
| terms | 공통 정의 및 용어 | (그대로) | 이 말은 무슨 뜻? |
| usage | 도메인 사용 가이드 | **자주 하는 작업** | 이런 상황에선 어떻게? |
| menus + procedures | 메뉴별 설명 + 메뉴별 사용 절차 | **메뉴 안내** (하나로) | 이 메뉴는 어디서 열고 뭘 할 수 있어? |
| permissions | 권한 안내 | (그대로) | 누가 열 수 있어? |
| flows | 대표 업무 흐름 | **상태 변화** | 한 건의 상태가 어떻게 바뀌어? |
| services | 연결 서비스 | (그대로) | 뒤에 어떤 서비스가 있어? |

탭 키는 그대로 둔다(딥링크 `#…-tab-usage` 등 보존). `procedures` 키만 없어진다.

- `shared/guide/DomainGuideTabs.tsx`: 키에서 `procedures` 제거 · 라벨 셋 변경 · `menusIntro`(메뉴 안내 자동 카드 위에 얹는 도메인 고유 내용) prop 추가.

- 도메인별 내용 재배치(AC-0 실측 결과):

| 도메인 | 옮긴 것 |
|---|---|
| Finance | 「사용 가이드」의 콘솔 화면 표 → 「메뉴 안내」 위 · 「업무 흐름」의 자주 하는 작업 → 「자주 하는 작업」 · 「상태 변화」 = 상태 흐름이 없다는 안내 + 계좌 상태(용어 탭) 안내 |
| ERP | 콘솔 화면 표 → 「메뉴 안내」 위 · 자주 하는 작업 → 「자주 하는 작업」 · 위임 스코프(정의) → 「공통 정의 및 용어」 · 결재 상태 → 「상태 변화」 그대로 |
| IAM | «2. 메뉴 사용법» 표 → 「메뉴 안내」 위 · 운영자 온보딩 순서(할 일 순서) → 「자주 하는 작업」 · 「상태 변화」 = 정리된 상태 흐름이 없다는 안내 |
| WMS · SCM · E-Commerce | 내용 이동 없음(이미 맞는 탭) — 안내 문구의 옛 탭 이름만 교체 |

- 각 가이드 «처음이라면 …» 안내 문구의 옛 탭 이름 교체(IAM · WMS · SCM · Finance · ERP · E-Commerce).
- `specs/services/console-web/architecture.md` 의 가이드 설명 한 줄.
- 시험: 공용 헬퍼가 7탭 이름 · 순서와 «메뉴 안내» 카드마다 «여는 곳» · «필요한 권한» 을 단언, 옛 `-menu-procedures` 부재 단언 · Finance/ERP/IAM 의 섹션 배치 기대값 갱신 · IAM 온보딩 순서가 「자주 하는 작업」, Finance/IAM 안내 문구가 「상태 변화」 안에 있는지.

## Out of Scope

- 전역 가이드(`/guide`)의 탭 — 「대표 업무 흐름」은 거기서 원래 뜻(메뉴를 거치는 일의 순서) 그대로.
- 각 섹션의 문구 자체(옮기기만 하고 다시 쓰지 않음). 단 새로 쓴 것은 Finance/IAM 「상태 변화」 안내 두 문단.
- WMS 「자주 하는 작업」 안의 «저재고 두 가지 의미», SCM 의 «설정» 설명 — 상황 대처에 쓰이는 참고라 그 탭에 둔다.

# Acceptance Criteria

- **AC-0** ✅ 실측: 여섯 도메인의 usage/flows 패널 내용 조사 — 자주 하는 작업이 IAM·WMS·SCM·E-Com 은 usage, **Finance·ERP 는 flows** 에 있었고, Finance·ERP usage 는 콘솔 화면 표, IAM flows 는 상태가 아니라 온보딩 순서였다. 그래서 이름만 바꾸면 Finance·ERP·IAM 에서 이름과 내용이 어긋난다 → 내용 이동 포함.

- **AC-2** ✅ «메뉴 안내» 카드마다 여는 곳 · 필요한 권한 · 화면 내용 · 용도 · 할 수 있는 조작. bite: `PermissionMapTable.tsx` 를 옛 판으로 되돌리면 WMS·SCM 가이드 시험 2개 빨강 → 복원.

# Edge Cases

- 옛 딥링크 `#…-tab-procedures`: 그 탭이 없어져 첫 탭이 열린다(존재하지 않는 해시와 같은 동작). 다른 탭 키는 그대로라 영향 없음.
- Finance · IAM 은 「상태 변화」에 정리된 상태 흐름이 없다 — 「정보 없음」 대신 왜 없는지와 어디를 보면 되는지를 적었다.

# Failure Scenarios

- 이름만 바꾸고 내용을 안 옮기는 경우 → Finance·ERP 「상태 변화」 탭에 자주 하는 작업이 뜨는 모순. 섹션 배치 시험이 잡는다.
- 메뉴 안내 카드에서 «여는 곳» / «필요한 권한» 이 빠지는 경우 → 공용 헬퍼가 카드마다 두 줄을 단언(bite 확인).

## Context — 재고 있는 사실만 (2026-09-15, 저장소 코드 읽기)

### 지금 익명 방문자가 보는 것

| 경로 | 무엇 | 근거 |
|---|---|---|
| `/` | `isAuthenticated()` 거짓 ⇒ `/demo` 로 리다이렉트 | `app/page.tsx:36-39` |
| `/demo`, `/demo/[domain]` | **별도 화면 2개** — 봉투(`console-sample`)의 표를 범용 `SampleTableCard` 로 그린다 | `app/(demo)/**` · `features/demo-tour/**` |
| `(console)/**` 65 화면 | 첫 줄 가드가 `/login?redirect=…` 로 튕긴다 | `app/(console)/layout.tsx:90` |

즉 방문자가 보는 «콘솔» 은 실제 화면이 아니라 **실제 화면을 흉내 낸 두 번째 UI** 다. 두 UI 는 이미 따로 늙는다 —
같은 날 `TASK-MONO-680` 이 `/demo` 의 버튼 문구만 따로 고치고 있다.

### 실제 화면의 데이터가 흐르는 길

- 페이지는 **전부 서버 컴포넌트**이고, 첫 데이터를 서버에서 `get*State()` 로더가 가져온다. 이후 페이지 이동·필터·쓰기는
  클라이언트가 `apiClient` 로 같은 오리진 `/api/**` 라우트 핸들러를 부르고, 그 핸들러가 **같은 로더/클라이언트**를 다시 쓴다.
- 백엔드로 나가는 호출은 **게이트웨이 코어 여섯**에 모여 있다. 모두 «토큰 확인 → `fetch(await resolveBackendUrl(url))`
  → 응답 해석» 의 같은 모양이다:

| 코어 | 파일 | 자격 |
|---|---|---|
| `callAdminGateway` | `shared/api/iam-gateway.ts` | 운영자 토큰 + `X-Tenant-Id` |
| `fetchRegistry` | `shared/api/registry-client.ts` | 운영자 토큰 |
| `callWmsGateway` | `shared/api/wms-gateway.ts` | 도메인 토큰 |
| `callEcommerceGateway` | `shared/api/ecommerce-gateway.ts` | 도메인 토큰 |
| `callFlatEnvelopeGateway` (+ `callScmGateway` 심) | `shared/api/flat-envelope-gateway.ts` · `scm-gateway.ts` | 도메인 토큰 |

- 🔴 **코어 밖의 구멍 다섯**: `api/console/dashboards/{operator-overview,domain-health}/route.ts` 와
  `api/console/notifications/{inbox,[sourceDomain]/[id]/read}/route.ts` 는 `CONSOLE_BFF_URL` 을 **직접** `fetch` 한다
  (`resolveBackendUrl` 도 안 거친다). `api/tenant/route.ts` 는 레지스트리 + 토큰 교환을 직접 한다.
- 🔴 **코어 밖에서 세션을 읽는 자리**: `(console)/layout.tsx`(계정 표시명 = `id_token` 디코드, 테넌트 목록),
  `(console)/account/page.tsx`, 그리고 `operators`·`subscriptions`·`partnerships` 페이지의 테넌트 선확인.

## 갈래

### A — 게이트웨이 경계에 **샘플 모드**를 둔다 (실제 라우트·실제 화면 그대로)

익명 요청이 `(console)` 에 들어오면 셸이 렌더되고, 백엔드로 나가야 할 호출은 **코어 안에서** 샘플 응답으로 바뀐다.
화면·로더·파서·에러 매핑은 **한 줄도 안 바뀐다** — 그래서 «실제 페이지» 다.

- **A1 판정** — 샘플 방문자 ⇔ 액세스 쿠키 **와** 운영자 쿠키가 **둘 다 없다**. 판정 함수는 `shared/lib/session.ts` 에
  하나만 둔다(«인증» 의 정의가 두 곳에 생기면 한쪽만 고쳐진다 — `app/page.tsx` 헤더의 같은 논거).
  🔴 반쪽 세션(pre-operator)·죽은 쿠키는 **지금 경로 그대로**다(온보딩·재로그인). 샘플이 되지 않는다.
- **A2 경계** — 코어 여섯 + 코어 밖 구멍 다섯(§ Context)이 **토큰을 읽기 전에** 샘플 여부를 묻는다. 샘플이면 샘플
  라우터가 만든 `Response` 를 **기존 응답 처리 코드에 그대로 먹인다**. 🔴 샘플 분기에서는 `fetch` 에 **도달할 수 없다**
  (분기가 네트워크 코드보다 앞이고, 샘플 라우터 모듈에는 네트워크 코드가 없다).
- **A3 샘플 라우터에는 백엔드로 가는 코드가 없다** — `@/shared/config/env`·`@/shared/lib/session`·전역 `fetch` 를
  임포트/호출하지 않는다. `ADR-MONO-070` D3 와 같은 축이고, 가드로 문다(금지 임포트 검사).
- **A4 데이터는 합성이다** — `ADR-MONO-070` D6 의 축을 그대로 가져온다. 샘플 응답은 **저장소가 손으로 쓴 픽스처**이고
  백엔드에서 뽑는 경로가 **존재하지 않는다**.
- **A5 쓰기(비-GET)** — 라이더 R1.
- **A6 «(샘플)» 표기** — 라이더 R2. 어느 쪽이든 셸 상단에 **상시 배너**(«샘플 데이터로 보는 실제 콘솔 화면 · 로그인하면
  실제 데이터»)가 붙는다. 🔴 배너는 **레이아웃**이 그린다(화면마다 붙이면 한 화면만 빠뜨릴 수 있다 — `SampleDataBanner`
  헤더의 같은 논거).
- **A7 셸의 익명판** — 계정 메뉴 자리에 «로그인»(`?redirect=<현재 경로>`), 테넌트 스위처는 샘플 테넌트 하나(읽기 전용),
  알림 벨은 샘플 알림. 🔴 `DemoHeartbeat`·`DemoBackendNotice` 는 **마운트하지 않는다** — 익명이 EC2 를 켜면 안 되고
  (`ADR-MONO-071` D8), 샘플 화면은 백엔드 상태와 무관하므로 «데모가 꺼져 있다» 는 **거짓 경고**다.
- **A8 URL 은 같다** — 익명도 `/dashboards/overview`·`/ecommerce/orders` 를 연다. `/` 는 누구든 `/dashboards/overview`.
  로그인하면 **같은 주소**에서 실제 데이터가 보인다.
- **A9 샘플이 아직 없는 GET** — 그 섹션을 기존 **섹션 degrade 상태**로 떨어뜨리고 문구는 «이 화면의 샘플 데이터는
  준비 중입니다». 🔴 셸과 다른 섹션은 멀쩡하다(`integration-heavy` 의 per-section degrade 를 그대로 쓴다). 그리고
  «어떤 GET 이 샘플을 갖고 있는가» 는 **원장**으로 두고 가드가 인벤토리와 대조한다(빈 칸이 조용히 늘지 않게).
- **A10 캐시** — `(console)` 은 이미 `force-dynamic` 이다. 🔴 그래도 «같은 주소가 쿠키에 따라 다른 본문» 이 되는 첫
  설계이므로, 실행 티켓이 «익명으로 연 뒤 로그인한 같은 브라우저에 샘플 문자열이 0» 을 e2e 로 잰다.

**얻는 것** — 요청 문장 그대로다. 두 번째 UI 가 사라지고, 방문자가 보는 화면이 곧 운영자가 보는 화면이라 **따로 늙을
수 없다.** 🔵 `e2e-smoke` 가 이미 백엔드를 전부 도달 불가 loopback 으로 고정해 두어서, «실제 화면이 네트워크 없이 선다» 를
**그대로 잴 자리**가 있다.

**포기하는 것 / 위험**
- 🔴🔴 **이 저장소에서 가장 비싼 한 줄의 의미가 바뀐다.** `(console)/layout.tsx:90` 은 «익명은 들어올 수 없다» 에서
  «익명은 들어오지만 백엔드에 닿을 수 없다» 가 된다. 안전의 근거가 **라우트 경계**에서 **코어 분기**로 옮겨간다.
  ⇒ 코어 밖으로 새 `fetch` 가 하나 생기면 그것이 곧 구멍이다. 🔵 다만 그 구멍으로 **실제 데이터가 새지는 않는다** —
  익명에게는 토큰이 없어 백엔드가 401 을 준다. 새는 것은 데이터가 아니라 «익명이 401 화면을 본다» 는 **품질 결함**이고,
  그 방향을 가드로 문다(§ Roadmap 1: `(console)` 트리에서 코어·샘플 라우터 밖의 `fetch` 금지).
- 샘플 픽스처 **94 GET** 을 손으로 쓴다. 도메인별로 나눠도 티켓 6~7개다.
- 쓰기 99 개가 한 번에 «샘플에서는 실행 안 됨» 이 된다(R1ⓐ 기준) — 폼·확인 대화상자까지는 보이고 마지막 제출만 막힌다.

### B — 같은 화면 컴포넌트를 쓰는 **별도 샘플 트리**(`/sample/**`)

`(sample)` 그룹이 `(console)` 의 `*Screen` 컴포넌트를 가져다 쓰고, 데이터는 로더 대신 픽스처를 **props 로 주입**한다.
가드는 안 건드린다.

- **얻는 것**: `(console)` 가드의 의미가 **그대로**다.
- **포기하는 것**: 화면 65개의 로더와 클라이언트 후속 호출(페이지 이동·필터)이 `apiClient` → `/api/**` 로 묶여 있어서,
  props 주입만으로는 **첫 화면만** 선다. 필터를 누르는 순간 `/api/**` 가 401 → `/login` 으로 튕긴다
  (`shared/api/client.ts:90-97`). 그걸 막으려면 클라이언트 경로에도 샘플 분기가 필요하고, 그러면 A 의 분기를 **두 곳**에
  갖게 된다. URL 도 달라서(`/sample/ecommerce/orders`) 링크·사이드바 경로를 이중으로 관리한다.

### C — 지금의 `/demo` 를 **콘솔 셸 모양으로 다시 입힌다**

데이터 경로는 봉투 그대로, 겉모습만 실제 콘솔(사이드바·헤더·도메인별 표 배치)에 맞춘다.

- **얻는 것**: 가장 싸다(티켓 1~2개). 가드·계약·테스트 기대값 전부 불변.
- **포기하는 것**: **요청 문장이 거절한 것 그대로다** — «데모페이지 대신 실제 페이지». 두 UI 가 계속 따로 늙는다.

## 라이더 — 갈래 A(와 B)에서도 **따로** 골라야 하는 것

🔴 아래는 갈래 글자를 골라도 **정해지지 않는다**(각 질문에 답하지 않고도 A 를 고를 수 있다 — rider 판별 기준).
그래서 accept 줄에 **각각의 글자**가 있어야 한다. 빠진 라이더는 «미결» 로 기록하고 구현하지 않는다.

| # | 질문 | ⓐ | ⓑ |
|---|---|---|---|
| R1 | 샘플 화면에서 **쓰기**(등록·승인·잠금 …)를 누르면? | **거부**한다 — `403 SAMPLE_READ_ONLY` + «샘플 화면에서는 실행되지 않습니다. 로그인하면 실제로 실행됩니다» (코어 한 곳에서 99개 전부) | **성공을 흉내 낸다** — 요청 수명 안에서만 바뀐 것처럼 보이고 새로고침하면 원래대로 |
| R2 | **«(샘플)»** 을 어디에 붙이나? | 배너 + 사람이 읽는 **문자열 값 끝**(이름·제목·설명 — 예: `김하나 (샘플)`). 🔴 id·코드·금액·날짜·상태 enum 에는 **안 붙인다**(파서·`StatusBadge` 가 그 값을 해석한다 — 붙이면 화면이 깨진다) | 배너 + 표 제목/카드 제목 옆 **배지**만. 값 자체는 자연스러운 합성값 |
| R3 | **어떤 순서로 공개**하나? | 기반 + 개요 먼저 공개하고 도메인별로 차례로 채운다(그 사이 빈 화면은 A9 의 «준비 중») | 94 GET 전부 채운 뒤 **한 번에** 전환(그때까지 `/demo` 유지) |

🔴 **R1ⓑ 는 되돌리기 쉽지만 거짓말에 가깝다** — 성공 토스트는 «실제로 실행됐다» 로 읽힌다. ⓐ 는 «무엇을 할 수 있는
화면인가» 를 폼까지는 보여 주고 마지막 한 걸음에서 사실을 말한다. 이 비대칭을 적어 둔다(고르는 것은 소유자다).

## Consequences (A 기준)

- `(console)` 의 안전 근거가 «라우트 가드» 에서 «코어 분기 + 코어 밖 fetch 금지 가드» 로 옮겨간다. 이 문장이 이 결정의
  가장 무거운 부분이고, 그래서 가드가 **기반 티켓의 AC** 다(나중으로 미루지 않는다).
- 새 화면을 만드는 사람은 **샘플 픽스처도** 만들어야 한다. 안 만들면 A9 원장 가드가 빨개진다 — 그것이 «두 UI 가 따로
  늙는다» 의 대체물이다(늙는 대신 빨개진다).
- `ADR-MONO-070` 의 봉투·발행 절차는 **팬·스토어에는 그대로** 남는다. 콘솔만 봉투 소비자에서 빠진다.
- `TASK-MONO-680`(같은 날, `/demo` 버튼 문구)의 콘솔 쪽 변경은 8 에서 함께 사라진다. 🔵 680 을 막을 이유는 없다 —
  8 전까지 방문자는 여전히 `/demo` 를 본다(R3ⓑ) 또는 그 사이 겹친다(R3ⓐ).

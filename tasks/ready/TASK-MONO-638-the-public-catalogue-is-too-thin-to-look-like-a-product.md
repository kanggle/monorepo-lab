# Goal

로그인 없이 보이는 세 화면의 데이터를 «둘러볼 만한 양» 으로 늘린다.

- **콘솔** — 로그인 없이 보이는 표본 확충
- **이커머스** — **카테고리별** 아이템 확충(지금은 카테고리당 1~2개)
- **팬** — 피드·아티스트 확충 + **아티스트 프로필 이미지**(지금 전부 `null`)

🔴🔴 **이 티켓의 어려운 부분은 «많이 쓰기» 가 아니라 «갈라지지 않게 늘리기» 다.** 공개
데이터는 두 곳에 산다 — 실제 시드 DB(기동하면 보이는 것)와 번들 시드(백엔드 없이 보이는 것).
한쪽만 늘리면 **기동 전후로 카탈로그가 달라지고**, 그 거짓은 «로그인하니 상품이 사라졌다»
라는 모양으로 나타난다.

# Acceptance Criteria

## AC-0 — 착수 전 실측 (verify-then-act)

- [ ] 세 스냅샷의 **현재 수량**을 다시 세서 적는다(위 표는 이 티켓 기안 시점의 값이다).
- [ ] `bin/build-bundled-snapshots.mjs` 를 **손대지 않은 트리에서 한 번 돌려** 산출물이
      커밋된 스냅샷과 **동일한지** 확인한다. 🔴 다르면 스냅샷이 이미 손으로 편집된 것이고,
      그때는 늘리기 전에 그 사실부터 처리해야 한다(늘린 뒤에는 원인을 못 가른다).

## AC-1 — 이커머스: 카테고리별로 볼 만해진다

- [ ] **모든 카테고리가 최소 4개** 이상의 공개 상품을 갖는다(지금은 1~2개).
- [ ] 🔴 `categories[].productCount` 가 **실제 공개 상품 수와 일치**한다. 지금은 우연히
      맞지만, 늘리면서 어긋나면 화면이 «6개» 라 써 놓고 3개를 그린다.
- [ ] 실제 시드에도 같은 상품이 들어간다 — 🔴🔴 **기존 `V8` 을 고치지 마라.** 이미 적용된
      볼륨에서 Flyway checksum 이 깨진다. **새 버전 마이그레이션**으로 추가한다.
- [ ] 🔴 `db/migration/` 과 `db/migration-h2/` **둘 다** 간다. 한쪽만 고치면 H2 로 도는 경로
      (`TASK-MONO-633` 이 조사 중인 그 경로)에서만 조용히 갈라진다.
- [ ] 상품 이미지는 **스토어가 이미 쓰는 방식**(Unsplash CDN URL)을 따른다 — 새 이미지
      호스트를 도입하지 않는다.

## AC-2 — 팬: 피드와 아티스트가 늘고, 얼굴이 생긴다

- [ ] 아티스트를 **최소 6명**으로 늘리고, 게시물을 아티스트마다 최소 2개(공개 1 + 잠금 1)
      갖도록 늘린다. 잠금 글이 있어야 «로그인하면 더 있다» 가 화면에서 참이 된다.
- [ ] 🔴🔴 잠긴 글은 `body` 와 `bodyPreview` 를 **둘 다 안 싣는다**(ADR-MONO-070). 늘리면서
      이 성질이 깨지지 않는지 **음성 대조군 시험으로** 확인한다.
- [ ] **`profileImageUrl` 을 채운다.** 🔵 소유자 결정(2026-09-08): **라이선스 인물사진
      (Unsplash)** 을 연결한다 — 스토어 상품 이미지와 같은 CDN·같은 계약이라 새 의존이 없다.
- [ ] 🔴🔴 **실존 인물을 참고하지 않는다.** 이 데모의 아티스트(루미·노아·세아 …)는 가공
      인물이고, 실존 연예인을 닮게 만들면 **실존 인물의 초상**이 포트폴리오에 들어간다.
      필요한 것은 «그럴듯한 아티스트 사진» 이지 «누군가를 닮은 사진» 이 아니다.
- [ ] 이미지가 **없거나 404 일 때의 폴백**이 화면에 있다(아바타/이니셜). 지금 값이 전부
      `null` 이므로 폴백은 **오늘의 정상 경로**이고, 회귀하면 얼굴 자리가 깨진다.
- [ ] 실제 시드(`seed-fan.sh`)에도 같은 아티스트·게시물이 들어간다.

## AC-3 — 콘솔: 로그인 없이 보이는 표본 확충

- [ ] 도메인별 `metrics`·`tables` 표본을 «화면이 비어 보이지 않을» 만큼 늘린다.
- [ ] 🔴 콘솔 공개 표본은 **백엔드 추출 경로가 없는** 큐레이션 데이터다. 그 사실을
      `console-sample.mjs` 머리말에 명시한다 — 나중 사람이 «추출이 고장났다» 로 오진하지 않게.
- [ ] 🔴 `(console)` 가드의 **행위를 바꾸지 않는다**(`TASK-MONO-635` 가 세운 경계).

## AC-4 — 두 벌이 갈라지지 않는다

- [ ] 🔴🔴 **가드 한 칸**: 번들 시드와 실제 시드가 **같은 것을 말하는지** 대조한다. 최소한
      이커머스 상품의 **키 집합**(id 또는 name)이 두 곳에서 같은지 본다.
      선례: `(z32)` 가 `projects.sh` ↔ `handler.py` 의 묶음 표를 같은 이유로 대조한다.
- [ ] 그 가드에 **하한을 두지 마라 vs 두어라를 먼저 판단하고 근거를 적는다.** 이 모집단은
      «늘어나는 것이 목표» 라 하한이 성립하지만, 줄어드는 모집단에 하한을 걸면 성공이
      고장난다(이 저장소가 7회 밟은 함정). 어느 쪽인지 **세어 보고** 정하라.
- [ ] **bite**: 한쪽에만 상품을 추가하면 그 가드가 빨개진다.

## AC-5 — 🔴🔴 이미지를 늘리면 **이미 초과된 축**을 더 민다

`TASK-MONO-587` 이 이름 붙인 축이 있다. Vercel **Image Optimization** 은 2026-08-26 실측에서
이미 **Transformations 5.6K/5K(112%)** · **Cache Writes 320K/100K(320%)** 였고, 2026-08-29
Pro 전환으로 «막힌다» 가 «청구된다» 로 바뀌었을 뿐 초과는 그대로다.

그리고 세 앱이 이 축을 **다르게** 탄다(실측 2026-09-08):

| 앱 | 이미지 처리 | 이 축을 타는가 |
|---|---|---|
| `web-store` | `next/image` + `remotePatterns: images.unsplash.com` | 🔴 **탄다** |
| `fan-platform-web` | `images: { unoptimized: true }` | 🟢 안 탄다 |
| 론처(`hubwang.com`) | 정적 HTML 의 `<img>`(빌드가 파일을 복사) | 🟢 안 탄다 |

- [ ] 🔴 **AC-1 이 상품을 늘리면 그만큼 변환 요청이 는다.** 늘리기 전에 «상품 N개 추가 =
      변환 몇 건 증가» 를 **산술로 적어라**(고유 이미지 수 × 렌더되는 크기 수).
- [ ] 그 증가분을 감당할지, 아니면 카탈로그 썸네일을 최적화 밖으로 뺄지는 **`TASK-MONO-587`
      의 삼지선다에 속한다.** 🔴 이 티켓에서 조용히 정하지 마라 — 측정치를 적고, 587 을
      인용해 소유자 결정이 필요한지 판단한 뒤 그 판단을 적는다.
- [ ] 🔵 팬 아티스트 이미지는 `unoptimized: true` 라 이 축에 **안 걸린다** — 그러므로 AC-2 는
      이 제약과 무관하게 진행해도 된다. 그 사실을 여기 적어 두는 이유는, 안 적으면 다음
      사람이 «이미지 = 할당량» 으로 뭉쳐서 걸리지도 않는 것을 막기 때문이다.

## AC-6 — 늘려도 성질이 유지된다

- [ ] `infra/demo/public-data` 패키지 시험이 **전부 통과**한다(현재 31/31 — 재측정해서 적는다).
- [ ] 🔴 누출 대조군이 **여전히 문다** — 늘린 픽스처에도 음성 대조군이 들어 있고, 변환기가
      그것을 지운다. 🔴🔴 **모집단이 커지면 «독립 grep 0건» 이 더 약한 증거가 된다**(찾을
      곳이 늘었다). 대조군을 **함께** 늘려라.
- [ ] `coverage`·`collectionStatus` 봉투가 늘어난 수량을 정확히 말한다 — 「정상적인 0건」과
      「수집 실패」를 가르는 필드이므로 수량이 틀리면 그 구별이 무의미해진다.

# Failure Scenarios

1. **`snapshots/*.json` 을 손으로 편집한다** → README 가 금지한 것이고, 다음 재생성에서
   조용히 되돌아간다. 그리고 그 되돌아감은 «데이터가 사라졌다» 로 보인다.
2. **번들 시드만 늘린다** → 기동 전에는 상품 30개, 기동 후 로그인하면 8개. 방문자에게는
   «로그인했더니 카탈로그가 줄었다» 로 보인다.
3. **기존 `V8` 마이그레이션을 고친다** → 기존 볼륨에서 Flyway checksum 실패. 🔴 신선 볼륨
   CI 는 **영구 초록**이라 이 결함을 못 잡는다.
4. **`migration-h2/` 쌍둥이를 빠뜨린다** → H2 로 도는 경로에서만 갈라지고, 그 경로는 지금

5. **이미지를 늘리면서 변환 할당량 증가를 안 센다** → 이미 112%/320% 인 축을 말없이
   더 민다. Pro 라 «막히지» 않고 **청구된다** — 즉 아무 화면도 안 빨개지고 청구서만 는다.
   `TASK-MONO-633` 이 조사 중이라 원인이 섞인다.
6. **음성 대조군을 지우거나 안 늘린다** → 누출 시험이 «아무것도 안 하면서 초록» 이 된다.
7. **실존 아티스트를 참고한 이미지를 넣는다** → 실존 인물의 초상이 포트폴리오에 들어간다.

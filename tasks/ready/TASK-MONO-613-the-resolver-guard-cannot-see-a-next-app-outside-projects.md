# 🔴 왜 이것이 «나중에» 가 아닌가

가드가 지키는 것은 코드 중복이 아니라 **결정**이다 — *"세 번째가 오면 `B` 로 승격할지
소유자가 정한다"*. 모집단에 구멍이 있으면 그 **결정 자체를 디렉터리 선택으로 건너뛸 수 있다**,
그리고 건너뛴 사실이 **아무 데도 남지 않는다.**

🔵 이 저장소는 같은 모양을 이미 여러 번 기록했다 — 가드가 안 무는 이유 중 «도달성»,
그리고 *"가드 **없는** 한 지점이 결함 자리"*.

# Acceptance Criteria

## AC-0 — 착수 시 재측정

1. `next.config.*` 전수와 그중 `projects/` 밖의 수. 🔵 오늘 = **3 / 0**.
2. 가드가 여전히 rc=0 이고 «해석기를 가진 앱 2 개 (승격 3)» 을 내는가.

## AC-1 — 모집단을 **선언에서** 유도한다

- `declared_apps()` = `next.config.*` 를 가진 **모든** 디렉터리 (경로 접두사 무관)
- `app_files()` = 그 앱들의 소스
- `fold_to_app()` = 파일 → **가장 긴 선언 앱 접두사**
- 🔴 기존 세 앱의 판정이 **바뀌지 않아야** 한다(오늘 값 = 앱 2개 / 비교 1쌍 / 소스 1191개 /
  선언 앱 3개 / 대조군 2건). **먼저 그 다섯 수를 고정하고 바꿔라.**

## AC-2 — 🔴 self-test 에 **`projects/` 밖 앱** 칸을 넣는다

- 합성 트리에 `infra/x/app/next.config.ts` + 해석기 파일을 놓고 **모집단에 잡히는지**
- 🔴 그 칸이 **현재 판에서 실패**하는지 먼저 확인한다(= bite). 안 하면 «고쳤다» 가 공허하다

## AC-3 — 대조군을 깨뜨리지 않는다

가드의 칸 (3)은 **론처(`infra/demo/aws/site/`)** 에서 `DEMO_API_BASE` 가 보이는지로 탐지기
생존을 확인하고, 그 근거는 *"론처는 모집단 **밖**"* 이다. 🔴 모집단을 넓히면 **론처가 안으로
들어올 수 있다** — 그러면 대조군이 자기 자신을 재게 된다.

🔵 론처에는 `next.config.*` 가 **없다**(정적 HTML) ⇒ 선언 기반 모집단에는 안 들어온다.
**그 사실을 단언으로 고정하라** — 나중에 론처가 Next 로 바뀌면 이 가드가 조용히 눈이 먼다.

# Edge Cases

- **`next.config.*` 가 있지만 Next 앱이 아닌 디렉터리** — 픽스처·템플릿. 오늘 0건이지만

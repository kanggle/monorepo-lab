# Goal

`.claude/commands/audit-memory.md` §2-6(인덱스 예산)이 지시하는 측정 방법을, 그 지시가 만들어 낸 **실측 결과에 맞춰** 고친다.

이 절은 스스로 *"정원을 상수로 믿지 말고 그 자리서 계산하라"* 고 적어 두었지만, **계산식 자체가 틀렸다** — 분자는 문자 한도(24,576)이고 분모는 바이트(포인터당 B)다. 서로 다른 단위를 나눈 값이 "상한 포인터 개수"로 유통됐고, 그 값 때문에 **한도 아래인 파일이 초과로 판정**된 적이 있다(한글 3바이트 → 20,361자가 28.6KB로 보임, 여유 4,215자가 있는데 초과처럼 읽힘).

정책 변경이 아니다. **명령이 시키는 측정이 재는 대상과 어긋나 있는 것**을 고치는 일이다.

# 배경 — 실측 (2026-08-23 UTC)

## ① 산술의 단위가 섞여 있다

현재 §2-6 ① 본문:

```
🔴 정원을 상수로 믿지 말고 그 자리서 계산하라 — 파일명이 길어지면 포인터당 바이트가
올라간다. `정원 = 24576 ÷ (포인터당 바이트)`.
```

- `24576` 은 **문자** 한도다(훅이 보고하는 값 = `String.length`).
- `포인터당 바이트` 는 `wc -c` 에서 나온 **바이트**다.
- 한글이 UTF-8 3바이트이므로 이 파일에서 **바이트 ≈ 1.35 × 문자**. 즉 이 나눗셈은 정원을 체계적으로 **과소** 산출한다.

②의 실측표(`상한 200 포인터` / `189 포인터`)도 같은 나눗셈의 산물이라 함께 무효다.

## ② 카운트 정규식이 포인터를 놓친다

현재 §2-6 ① 의 스니펫:

```bash
ptr=$(grep -oE '\]\([a-z0-9_]+\.md\)' MEMORY.md | wc -l)
```

`[a-z0-9_]` 는 **하이픈·마침표·대문자**를 못 받는다. 실측(2026-08-23 `MEMORY.md`):

| 패턴 | 결과 |
|---|---:|
| `[a-z0-9_]+` (현행) | **184** |
| `[a-zA-Z0-9_.-]+` | **189** (고유 186) |

놓치는 5건 = `](ARCHIVE.md)` · `](PLAYBOOKS.md)` 및 하이픈이 들어간 `*_detail_*` 파일명. **훅이 세는 값과 명령이 세는 값이 다르면, 명령은 훅이 왜 울리는지 설명하지 못한다.**

## ③ 실측한 현재 값 (이 티켓의 기준선)

```
MEMORY.md    21,137자 / 189 포인터 (고유 186)   한도 24,576자   여유 3,439자 = 14.0%
PLAYBOOKS.md  4,488자 /  39 포인터
ARCHIVE.md   17,581자 /  71 포인터
포인터 경로 `](….md)` = 9,756자 = MEMORY.md 의 46% — 압축 불가(주소다)
```

⇒ **문자 축으로는 WITHIN 인데 훅(포인터 개수 축)은 발화한다.** 두 축이 다르다는 것 자체가 §2-6 이 말해 줘야 할 사실인데 지금은 둘을 섞어 놓았다.

## ④ 정경은 이미 철회를 기록해 두었다

메모리 `feedback_memory_index_one_line_discipline` § *"2026-08-22(UTC) — 정원제(포인터 세기)는 철회한다. 단위가 틀렸다"* 가 이 철회의 보유자이고, `MEMORY.md` 헤더도 이미 문자 축으로 고쳐져 있다. **명령 파일만 철회 이전 상태로 남았다** — 그리고 명령이 다음 세션의 실제 행동을 지시하는 쪽이다.

2. 같은 절의 카운트 정규식을 `[a-zA-Z0-9_.-]+` 로 교정.
3. §2-6 ② 실측표 — 철회된 나눗셈에서 나온 "산술 상한" 행을 제거하고, **문자 대 포인터경로 비율**(압축 여지 판정)로 대체.
4. §2-6 ③ 에 **두 축이 다르다**는 한 줄 추가: 토큰 비용 = 문자, 훅 판정 = 포인터 개수. 산문을 깎아도 훅은 안 꺼진다.
5. §3 보고서 템플릿의 예산 줄을 문자 축 표기로 정렬.
6. `tasks/INDEX.md` 행 이동.

## Out of Scope

- **`.claude/hooks/` 의 훅 자체를 문자 축으로 바꾸는 것** — 별개 결정이고, 훅의 임계를 바꾸면 정원 정책을 바꾸는 것이라 소유자 사안이다. 이 티켓은 **명령이 측정을 정직하게 하도록** 만드는 데까지다.
- **`MEMORY.md` 를 실제로 압축하는 것** — 현재 WITHIN(여유 14.0%)이라 할 일이 없다.
- **§2-6 ③④⑤ 의 정책**(이동 우선순위 · 함정 강등 금지 · 포인터 집합 동등성 술어) — 전부 유효하고 이 티켓과 무관하다.

# Acceptance Criteria

## AC-0 — 착수 시점 재측정 (verify-then-act)

```bash
M=~/.claude/projects/c--Users-kangdow-dev-project-ai-project-monorepo-lab/memory
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');
  const m=s.match(/\]\([a-zA-Z0-9_.-]+\.md\)/g)||[];
  console.log(s.length+'자', m.length+'ptr', '경로'+m.reduce((a,b)=>a+b.length,0)+'자')" $M/MEMORY.md
grep -n '24576 ÷\|a-z0-9_\]+' .claude/commands/audit-memory.md
```

- 명령 파일에 위 두 문자열이 **여전히 있어야** 한다. 없으면 누가 이미 고친 것이므로 STOP 하고 티켓을 닫는다.
- 문자 수·포인터 수가 위 ③과 달라도 **AC-1 은 그대로 진행한다** — 근거는 숫자가 아니라 **단위 오류**다.

## AC-1 — 산술 교정

- §2-6 이 **총 문자 수**를 1차 지표로 지시하고, 한도 24,576자를 문자로 명시한다.
- `24576 ÷ (포인터당 바이트)` 형태의 나눗셈이 파일에서 **0건**이다 (`grep -c '24576 ÷'` = 0).
- 측정 스니펫이 `wc -c` 가 아니라 `readFileSync(…,'utf8').length` 를 쓴다.

## AC-2 — 카운트 정규식 교정 + 대조군

- 파일의 모든 포인터 카운트 스니펫이 `[a-zA-Z0-9_.-]+` 를 쓴다.
- 🔴 **교정을 전역치환으로 하지 않는다.** §2-6 ④ 의 동등성 술어 스니펫도 같은 정규식을 쓰는데, 그 둘은 같은 값을 세야 의미가 있다 — 고친 뒤 **④ 술어를 실제로 한 번 돌려** 양방향 `comm` 이 공집합인지 확인한다.
- **대조군**: 교정 전 정규식과 교정 후 정규식을 같은 파일에 돌려 **다른 값**(184 ≠ 189)이 나오는 것을 PR 본문에 붙인다. 같은 값이 나오면 놓친 5건에 대한 내 판독이 틀린 것이므로 STOP.

## AC-3 — 두 축의 분리가 명시된다

§2-6 에 다음이 문장으로 존재한다:

- 토큰 비용의 축 = **문자 수**, 훅 발화의 축 = **포인터 개수**.
- 따라서 **산문 압축은 훅을 끄지 못한다** — 포인터를 줄이지 않는 한 계속 발화한다.
- 그리고 한쪽이 WITHIN 인데 다른 쪽이 발화하는 상태는 **정상**이며, 그때 할 일은 압축이 아니라 재고(문자 대 포인터경로 비율)다.

🔴 이 절이 *"압축해라"* 만 전달하고 *"이미 두 번 해봤고 안 통한다"* 는 못 전달해서 같은 헛수고가 세 번 반복됐다. **규칙이 아니라 실측 숫자를 남긴다** — 단, 그 숫자가 **무엇을 잰 것인지 함께** 적는다(옛 "0.8%" 가 *줄 병합* 을 잰 값인데 *산문 전체* 에 대한 주장으로 읽혀 유효한 선택지를 지웠다).

## AC-4 — 보고서 템플릿 정렬

§3 의 `### 6. 인덱스 예산` 예시가 `N자 / P 포인터 (한도 24,576자) — 여유 R자 (X%)` 형태이고, 바이트 표기가 남아 있지 않다.

## 실측 — 지금 배포된 둘은 **다른 세대다**

```
서빙 중인 론처   = 737f57022  (TASK-MONO-625)   ← check-launcher-fresh.sh 가 md5 로 확인
배포된 AMI       = ami-0fc6e4b7ac34c4ef5, bake 2026-09-03T19:33Z  ← TASK-MONO-624 기동 기록
                    ⇒ 그 안의 demo-up.sh 는 최대 9271aec32(617, 09-03)
                    ⇒ afebc9371(618, 09-04) · 737f57022(625, 09-06) **둘 다 없다**
```

🔴 **그러므로 배포된 `demo-up.sh` 는 「vercel 행은 안 찌른다」 + 「하한 2」 세대이고, 서빙 중인
론처는 「세 행이 전부 vercel · console 만 `data-demo-probe`」 세대다.** 그 조합에서 찌를 표면은
**0개**이고 하한은 2 이므로 부팅 판정은 `판정 불가` 로 `final_rc=1` 이 된다.

🔴 **그러나 이것을 「부팅이 깨졌다」로 단정하지 않는다.** 배포된 파일을 직접 읽지 않았고
(그러려면 기동해서 SSM 으로 들어가야 한다), 위는 **커밋 세대에서 유도한 것**이다.
`TASK-MONO-624` 기동 창(2026-09-05 05:44 UTC)은 `625` **이전**이라 이 조합을 겪지 않았다 —
즉 **이 조합으로 부팅한 사람이 아직 아무도 없다.**

⇒ **그것이 이 티켓의 요지다: 아무도 안 재고, 재는 것도 없다.**

# Edge Cases

① 🔴 **후보 a 는 첫 회를 못 잡는다.** 그 코드가 AMI 안에 있기 때문이다 — 낡은 AMI 에는
   그 검사도 없다. 「가드를 넣었으니 됐다」로 닫으면 **정확히 잡아야 할 그 한 번**을 놓친다.

② 🔴 **AMI 를 다시 구우면 어긋남이 사라진다.** 그러면 bite 가 **공허해진다** — 그래서
   AC-2 는 «지금 어긋나 있다» 가 아니라 **주입**으로 무는 것을 요구한다.

③ 🔵 론처는 Vercel 이 자동 배포하므로 «머지 = 배포» 다. 이 비대칭 자체는 **결함이 아니라
   설계**다(`TASK-MONO-579` 가 론처의 집을 Vercel 하나로 만들었다). 고칠 것은 배포 속도가

# Failure Scenarios

① **가드를 만들고 러너에 안 붙인다** → 초록인 채 한 번도 안 돈다(`(z16)` 이 실측한 모양).

② **정적 가드로 만족한다** → 저장소 안의 두 파일은 **항상 서로 맞는다**(같은 커밋에서 읽으므로).
   그 초록은 배포 경계에 대해 **아무것도 말하지 않는다.**

③ **어긋남을 «부팅 실패» 로만 표현한다** → 「데모가 안 떴다」와 구별되지 않는다. 사유가
   이름을 가져야 한다.

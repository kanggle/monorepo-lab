# 🔵 이 저장소에 **같은 모양의 선례가 이미 있다**

`check-label-drift.sh`(`TASK-MONO-553`)가 구조적으로 동일한 문제를 푼다 — *"초록인데 실제로는
틀린 것을 렌더/`ps` 로는 못 본다"*. 그 헤더가 대리지표를 하나씩 기각한다:

```
· docker ps        → 초록이다. 옛 컨테이너도 running + healthy 다.
· demo-status.sh   → 컨테이너를 셀 뿐 «어느 주소로 열리는지» 모른다.
· compose 종료코드 → 0 일 수 있다.
· HTTP 200         → 옛 호스트명으로 물으면 열린다.
⇒ 어긋난 것은 오직 라벨 안의 호스트명이었다. 그러니 라벨을 직접 읽는다.
```

배선도 같이 있다: `demo-up.sh:410` 이 부팅마다 `post_up_call` 로 돌리고,
`verify-demo-wrapper.sh` **(z5)** 가 *"그 스크립트가 존재하는가"* 를 정적으로 지킨다.
⇒ **런타임 관측자 + 그 관측자의 존재를 지키는 정적 가드**라는 쌍이 이 저장소의 기존 형태다.

# Acceptance Criteria

## AC-0 — 착수 시 **다시 잰다** (verify-then-act)

1. `(z19)` 가 여전히 **렌더 전용**인지 확인한다(`docker compose config` 다섯 칸 + 바닥 20).
   🔴 그 사이 누가 런타임 칸을 넣었으면 이 티켓의 크기가 달라진다.
2. **(f) 벽이 여전한지** 확인한다 — 그 사이 `container_name` 고정이 풀렸으면 후보 B/C 의
   판정이 바뀐다.
3. 🔵 오늘 데모 호스트에 억제 대상 컨테이너가 **없다**는 것이 616 창 #3 에서 재확인됐다
   (`web.ecommerce` 404). ⇒ **현 상태는 정상이고, 이 티켓은 회귀를 막는 것**이다.
   🔴 그래서 **bite 없이는 아무것도 증명되지 않는다**(AC-3).

## AC-1 — 판정 자리를 고르고 **왜 나머지를 버렸는지** 적는다

위 A/B/C 중 하나. 🔴 **C 는 고를 수 없다**(도달 불가). 고른 이유를 파일 헤더에 적는다 —
기전과 술어를 따로 고르면 가드가 영원히 공허하다(`TASK-MONO-604` AC-1 이 배운 것).

## AC-2 — 술어는 **런타임**이지 선언이 아니다

- 판정 대상은 `docker ps -a` / `docker inspect` **출력**이다. 🔴 **compose 파일 grep 금지**,
  **렌더 grep 금지** — 그 둘은 (z19)가 이미 본다. 이 칸이 사는 이유는 **둘이 갈릴 때**다.
- **모집단**: 「억제 선언된 서비스」를 **선언에서 유도**한다(하드코딩한 서비스 이름 목록 금지).
  🔴 하드코딩하면 단계 3·4 에서 같은 결함이 조용히 재발한다.
- 🔴 **`docker ps` 만 보지 마라** — 되살아나는 컨테이너는 `Exited` 상태로도 존재한다.
  `-a` 로 **존재**를 본다(616 창 #3 이 C1 을 그렇게 판정했다).

## AC-3 — 🔴🔴 **bite. 주입을 먼저 단언한다**

- **주입**: 억제 대상 서비스의 컨테이너를 **일부러 만든다**(예: 억제 파일을 뺀 체인으로
  `up -d --no-start` 하나만). 🔴 주입이 **실제로 그 컨테이너를 만들었음**을 먼저 단언한다 —
  주입 안 된 초록을 bite 실패로 오독하는 것이 이 저장소가 반복해서 밟은 함정이다.
- **판정**: 가드가 **rc≠0** 이고, 메시지가 *어느 컨테이너가·어느 억제 선언에 대해* 남아
  있는지 이름을 댄다.
- **대조군**: 주입 전에는 **rc=0** 이어야 한다. 한쪽만 보면 「항상 문다」와 구별되지 않는다.
- 🔴 **정리**: 주입한 컨테이너를 반드시 지운다.

## AC-4 — 공허 통과와 영구 빨강을 **둘 다** 막는다

- 🔴 **바닥**: `docker ps -a` 가 **0행**을 내면(데몬 없음·권한 없음) 그것은 「깨끗함」이 아니라
  **판정 불가**다 — FAIL 또는 명시적 `skip` 으로 갈라라. 조용히 통과시키지 마라.
  [[env_empty_detector_output_is_not_absence]]
- 🔴 **데모가 아닌 곳**(로컬·CI): 억제 자체가 데모 프로파일에만 걸리므로 이 판정도
  **데모 컨텍스트에서만** 의미가 있다. 로컬에서 빨강을 내면 그 가드는 꺼진다.

## AC-5 — 정적 짝을 둔다

`(z5)` 가 `check-label-drift.sh` 에 대해 하는 것과 같은 형태로, **이 판정자가 존재하고
부팅 경로에 배선돼 있는지**를 정적으로 지킨다. 🔴 배선이 빠지면 파일은 있는데 **효력이 0**
이고 그 상태는 조용하다(`TASK-MONO-604` (z19) 첫 칸이 같은 이유로 있다).

## AC-6 — 이 구현이 **안 고치는 것**을 적는다

- 억제 기전 교체(604 § 남은 일 2·3)
- **(f) 벽** — 이름만 적는다. 고치면 별 티켓
- 단계 3·4 의 억제(→ `TASK-MONO-618` 및 console 몫)

# Edge Cases

- 🔴 **억제 대상이 `Exited` 로 존재**하는 경우 — `docker ps` 만 보면 놓친다. `-a` 로 본다.
- 🔴 **compose 프로젝트 이름**이 짧은 슬러그라 `--filter name=` 만으로는 남의 스택을 잡을 수
  있다. 프로젝트(`-p`)로 좁혀라 — 이미지 필터로 소유권을 판정하지 마라.
- 🔴 데모 호스트에서 **여러 프로젝트가 같이 돈다**(99 컨테이너 관측). 모집단을 안 좁히면
  판정이 시끄러워지고, 시끄러운 가드는 꺼진다.
- 🔵 **판정이 부팅을 실패시켜야 하는가** — 이 티켓은 «관측»을 만드는 것이고, 부팅 유닛을
  빨갛게 만들지 여부는 별개 선택이다. AC-1 에서 명시하라(`check-label-drift.sh` 의
  `drift_rc` 처리가 선례다).

2026-09-09 UTC 실측. 지원 자료로 쓸 만한 것이 **이미 넷** 있고, 넷 다 **다른 독자**를
겨냥해 쓰였다:

| 있는 것 | 실제 독자 | 지원 자료로 쓸 때의 문제 |
|---|---|---|
| `README.md` (루트, 256행) — 스스로 *"portfolio hub"* 라 선언 | **이 저장소를 클론할 개발자** | 목차의 절반이 `Getting Started`·`hosts 파일 등록`·`Traefik 기동`이다. 채용 담당자는 클론하지 않는다 |
| `docs/guides/interview-demo-walkthrough.md` (426행) | **면접에 들어온 사람 + 안내하는 본인** | 「§1 기동 → `demo-up.sh`」로 시작한다. 서류 단계에서는 아무도 기동하지 않는다 |
| `projects/<name>/README.md` × 8 | **그 서비스 리포에 온 사람** | 서비스 하나씩만 보여준다. **여덟을 관통하는 이야기가 없다** |
| 론처 `infra/demo/aws/site/index.html` | **데모를 켜 보려는 사람** | 켜는 것이 목적인 페이지다 |

🔵 **넷 다 잘못 쓰인 게 아니다 — 각자의 독자에게 맞다.** 없는 것은 **다섯 번째 독자**를
위한 것이다: **아무것도 실행하지 않고, 로그인하지 않고, 5분만 쓰는 사람.**

# 🔴🔴 착수 전에 소유자가 답해야 하는 것 — 형태가 정해지지 않았다

이 티켓은 **형태를 정하지 않은 채 기안한다.** 정하는 것이 소유자의 몫이고, 잘못 고르면
전부 다시 써야 하기 때문이다. 후보 셋:

| | 형태 | 사는 곳 | 좋은 점 | 나쁜 점 |
|---|---|---|---|---|
| **A** | 루트 `README.md` 를 **채용 담당자 우선**으로 재배치 | 이미 있는 파일 | 새 파일이 안 생긴다. GitHub 첫 화면이 곧 포트폴리오 | 🔴 개발자 독자를 밀어낸다. 지금 이 파일은 **둘 다** 하려다 둘 다 얕다 |
| **B** | `docs/portfolio.md` 신설 | 저장소 안 | 독자를 안 섞는다. 루트 README 에서 **맨 위 한 줄로** 링크 | 🔴 저장소에 문서가 하나 더 는다. 그리고 §6 처럼 **낡는다** |
| **C** | 저장소 **밖** (Notion·PDF·개인 사이트) | 리포 밖 | 채용 담당자가 익숙한 형태. 이력서와 같이 둔다 | 🔴🔴 **게이트가 없다** — 이 저장소의 어떤 검사도 그것이 낡았는지 못 잰다 |

🔴 **내 추천은 B 다** (분석=Opus 5). 사유는 하나뿐이다: **A 는 이미 실패한 적이 있다.**
루트 README 가 스스로를 *"portfolio hub"* 라 부르면서도 목차의 절반이 로컬 개발 절차인
것이 바로 「한 파일이 두 독자를 섬기려 한」 결과다. **C 는 낡음을 못 잰다** — 이 저장소가
가장 자주 데인 축이고(`feedback_figure_nothing_can_fail_will_drift`), 하필 **지원자가
건네는 문서**가 낡으면 대가가 크다.

🔴🔴 **그러나 이것은 추천이지 결정이 아니다.** `TASK-MONO-648` AC-2 에서 정확히 이 구분이
문제가 됐다 — 내 1순위 추천이 「소유자 승인 목록」으로 굳었고, 나중에 그 장이 설계상
저하한다는 것이 드러났다. **AC-0 이 답을 받기 전에는 착수하지 마라.**

# Goal

`.claude/commands/audit-memory.md` § Phase 2-6 이 인용하는 예산 상수를 **각 게이트가 실제로
재는 축에 맞게** 정정한다. 지금 그 절은 한 축(문자)만 있다고 말하면서 다른 축(바이트)의
상수를 그 자리에 놓아, 감사를 도는 에이전트가 **매번 틀린 여유를 보고**한다.

🔴 **고치는 것은 숫자 하나가 아니라 「축이 둘이다」는 사실**이다. 숫자만 바꾸면
같은 오류가 다음 정정에서 반대 방향으로 재발한다(아래 § 이력 참조 — 이미 세 번 그랬다).

# Context — 실측 (2026-08-27 UTC, `origin/main` = `f77f239ec`)

## ① 무엇이 틀렸나

`.claude/commands/audit-memory.md` 의 세 자리:

| 줄 | 현재 문구 | 문제 |
|---|---|---|
| 71 | *"훅이 보고하는 값도, 한도 **24,576** 도 **문자**다"* | **양쪽 다 거짓.** 훅은 바이트를 보고하고, 24576 은 그 훅의 바이트 상수다 |
| 184 | 보고서 템플릿 — *"한도 24,576자, 여유 R자"* | 문자 축에 **바이트 상수**를 대입 |
| 199 | Summary 템플릿 — *"(한도 24,576자)"* | 같음 |

## ② 훅의 소스가 말하는 것

`.claude/hooks/memory-budget-check.ps1` (단일 커밋 `4a8fd07cc`):

```powershell
$QuotaPointers  = 180     # 판정에 쓰이는 유일한 값
$HardLimitBytes = 24576   # 주석 스스로 "참고용(보고에만 사용)"
$bytes = [System.Text.Encoding]::UTF8.GetByteCount($text)   # ← 문자가 아니라 바이트
$ptr   = ([regex]::Matches($text, '\]\([a-z0-9_]+\.md\)')).Count
if ($ptr -le $QuotaPointers) { exit 0 }                     # ← 판정은 포인터 개수
```

⇒ 이 훅에 **문자 축은 존재한 적이 없다.**

## ③ 그런데 문자 축은 실재한다 — 다른 게이트다

하네스(Claude Code) 자신의 메모리 읽기 훅이 **문자**로 잰다. 실측 발화 문구:
*"MEMORY.md is 20.9KB, approaching the 24.4KB read limit. Compact it to under 17.1KB"*.
대조 — 그때 chars 21,388 ÷ 1024 = **20.9KB 일치**(bytes 로는 29.9KB, utf16 은 41.8KB).

| 게이트 | 재는 것 | 한도 | 판정자 |
|---|---|---|---|
| 하네스 메모리 훅 | **문자 수** | **24.4KB ≈ 24,986자** (압축 목표 17.1KB ≈ 17,510자) | 하네스 |
| `memory-budget-check.ps1` | **포인터 개수** | **180** (24576 바이트는 보고 전용) | 리포 훅 |

**두 축은 어긋나는 것이 정상이다** — 한쪽이 WITHIN 인데 다른 쪽이 발화할 수 있다.

## ④ 🔴 왜 지금 중요한가 — 오늘 감사가 이것에 걸렸다

2026-08-27 `/audit-memory` 실행 시 실측: `MEMORY.md` = **20,129자 / 180 포인터**.
커맨드 지시대로면 *"한도 24,576자, 여유 4,447자(18.1%)"* 로 보고해야 하는데,
실제 문자 게이트 기준 여유는 **4,857자(19.4%)** 다. 🔵 **오늘은 판정(WITHIN)이 안 뒤집혔다** —
그래서 더 위험하다. **틀린 상수가 옳은 결론을 내는 동안은 아무도 안 본다.**

🔴 **뒤집히는 구간이 실재한다**: 20,129자는 이미 압축 목표(17,510자)를 **+2,619자** 넘었고,
파일이 24,576~24,986 사이에 들어가면 **커맨드는 OVER, 실제 게이트는 WITHIN** 으로 정반대가 된다.

## ⑤ 🔴🔴 이 오류는 «틀린 숫자» 가 아니라 «틀린 정정의 화석» 이다

같은 사실이 **네 번** 잘못 적혔고, 매번 앞의 것을 고치면서 새로 틀렸다:

| 시점 | 무엇을 주장했나 | 왜 틀렸나 |
|---|---|---|
| ~08-21 | 정원 = `24576 ÷ 포인터당바이트` = 176 포인터 | **분자는 문자, 분모는 바이트** — 단위를 섞어 나눴다 |
| 08-22 | "정원은 총 **문자** 수, 한도 24,576자" | 훅을 안 읽고 썼다. 훅에 문자 축이 없다 |
| 08-23 | "문자 축은 **없다**" | 훅을 **하나만** 읽고 닫았다 — 하네스 훅이 그 편집을 저장하는 순간 발화해 반증했다 |
| 현재 | 커맨드 L71/184/199 = 08-22 판의 잔존 | 메모리는 정정됐는데 **리포 파일이 안 따라왔다** |

🔴 **교훈이 이 티켓의 절반이다**: 앞의 셋은 전부 관측된 **숫자**만 고쳤고 아무도
**계측기를 열지 않았다.** 그리고 08-23 은 하나를 열고 «없다» 로 닫았다 —
**출처가 둘일 수 있다. 하나를 읽은 것은 부재의 증거가 아니다.**

# Acceptance Criteria

## AC-0 — 착수 시 **두 훅을 다 열어서** 상수를 재확인한다 (상속 금지)

🔴 **아래 표의 숫자를 이 티켓에서 베끼지 마라.** 착수 시점에 직접 읽는다:

1. `.claude/hooks/memory-budget-check.ps1` — `$QuotaPointers` · `$HardLimitBytes` ·
   판정식(`-le`) · 정규식 리터럴을 **소스에서** 읽는다.
2. 하네스 문자 한도 — 훅 소스에 접근할 수 없으므로 **발화 문구가 유일한 출처**다.
   문구를 인용할 때 **관측 일자를 함께 적는다**(값이 바뀌면 인용이 낡는다).
3. 둘이 이 티켓의 서술과 다르면 **티켓이 아니라 소스가 맞다** — 차이를 AC-4 에 기록.

🔵 **양성 대조군**: 정정 후 `MEMORY.md` 를 실측했을 때 두 축의 판정이 각각
「WITHIN(문자)」·「180/180 미발화(포인터)」로 나와야 한다(08-27 실측값).

## AC-1 — L71 을 **축이 둘이라는 서술**로 바꾼다

숫자만 갈아 끼우지 않는다. 그 문단이 답해야 하는 것:

- 어느 게이트가 **무엇을** 재는가 (문자 / 포인터 개수)
- 각 게이트의 **판정 임계**와, 그것이 **판정용인지 보고용인지**
- 🔴 **바이트는 어느 게이트의 판정에도 안 쓰인다**는 명시 (`wc -c` 오독 방지 문단은 유지)

🔴 **§ ② 표(“내가 주장한 것 vs 소스”)를 커맨드에 복제하지 마라** — 그 이력은 메모리
`feedback_memory_index_one_line_discipline` 이 유일본이다. 커맨드에는 **결론과 포인터만**.

## AC-2 — 보고서 템플릿 두 줄(L184·L199)이 **두 축을 다 출력**하게 한다

지금은 한 줄에 한 축만 들어가서, 감사자가 어느 축을 보고 WITHIN 이라 했는지 알 수 없다.
🔴 **각 숫자는 자기가 무엇을 잰 것인지 이름을 달고 나와야 한다** — «20,129자» 가 아니라
«20,129자 / 문자 한도 24,986». 그리고 **두 판정이 어긋나는 것이 정상**임을 템플릿 자체가
말해야 한다(§ 2-6 ② 본문에는 이미 있는데 템플릿에는 없어서, 템플릿만 채우면 사라진다).

## AC-3 — 🔴 **커맨드 전체에서 `24,576`/`24576` 을 전수하고 각각을 판정한다**

L71/184/199 은 **내가 grep 한 것**이고 모집단이 아니다. 남는 자리마다 셋 중 하나로 처리:
① 문자 축 문맥 → 정정 · ② 훅의 바이트 상수를 말하는 자리 → **보고 전용임을 명시하고 유지** ·
③ 철회된 산술(§ 2-6 ③ 의 `24576 ÷ …`)을 **인용**하는 자리 → 인용이므로 **byte-unchanged 유지**.

🔴 **③ 을 «정정» 하면 그 절이 경고하려던 오류 자체가 지워진다.**

## AC-4 — 메모리 쪽과 **어긋나지 않게** 닫는다

정정 후 `feedback_memory_index_one_line_discipline` 과 `MEMORY.md` 헤더가 같은 것을 말하는지
대조하고, 어긋나면 **어느 쪽이 맞는지 근거와 함께** 적는다.
🔵 08-27 감사 시점엔 **메모리 두 곳이 이미 정정본**이고 커맨드만 낡았다.

🔴 **이 티켓이 안 하는 것**: 정원 180 의 **값 자체**는 안 건드린다. 그 임계는 철회된
산술의 산물이라 근거가 없지만, 바꾸는 것은 **매 세션 토큰을 더 쓸지의 소유자 결정**이다.
이 티켓은 «커맨드가 훅을 정확히 서술하는가» 만 다룬다.

# Edge Cases

- **하네스 한도가 바뀌어 있다** → 발화 문구가 유일한 출처이므로 **관측 일자를 붙여** 기록하고,
  못 관측하면 «미관측» 으로 적는다. 🔴 추정치를 상수로 적지 마라 — 이 파일이 세 번 그렇게 틀렸다.
- **정정 중 `MEMORY.md` 가 실제로 초과한다** → 이 티켓은 **커맨드만** 고친다.
  초과 해소는 § 2-6 ③ 절차(ARCHIVE/PLAYBOOKS 이동)이고 **소유자 결정**이 낄 수 있다.
- **`24576` grep 이 0건** → 이미 누가 고쳤다는 뜻. 🔴 **0을 결과로 믿기 전에 양성 대조군**
  (`QuotaPointers` grep 이 훅에서 잡히는지)을 먼저 돌려라.
- **커맨드 파일이 `.claude/` 라 분류기에 막힌다** → 🔴 이 편집은 **산문**이지 권한·역할 목록이
  아니라 통과할 가능성이 높다. **먼저 시도**하고, **실제 차단 시에만** 패치를 사용자에게 넘긴다.
  표를 보고 미리 넘기지 않는다.

# Failure Scenarios

- **숫자만 갈아 끼운다** → § ⑤ 의 네 번째 재발이 된다. AC-1 이 요구하는 것은 **축의 서술**이다.
- **커맨드는 고쳤는데 보고서 템플릿이 옛 문구** → 다음 감사가 템플릿을 채우며 **틀린 상수를 부활**시킨다.
  템플릿은 산문이 아니라 **다음 실행의 입력**이라 더 강하게 전파된다.
- **철회된 산술 인용까지 «정정»** → 그 절이 보존하려던 반례가 사라지고, 같은 나눗셈이 다시 나온다.
- **«고쳤다»를 grep 결과로 보고** → 🔴 판정은 grep 이 아니라 **커맨드를 실제로 한 번 돌려**
  보고서 두 줄이 두 축을 이름과 함께 출력하는지 보는 것이다.

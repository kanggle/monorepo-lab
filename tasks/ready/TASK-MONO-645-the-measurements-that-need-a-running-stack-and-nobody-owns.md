## 🔴🔴 착수 게이트 — **2026-09-08 정정: 전제가 뒤집혔다. 이제는 켤 이유가 있다**

이 티켓의 첫 판은 *"이것만을 위해 EC2 를 켜지 마라 — 소유자가 다른 이유로 켜는 창이 열릴 때

### 왜 — 재굽기가 측정 대상을 파괴한다

| 실측 (2026-09-08 UTC) | 값 |
|---|---|
| 인스턴스 볼륨 | **루트 하나뿐** — `/dev/sda1` = `vol-078894f6d649d2b5e` |
| 별도 EBS 볼륨 리소스 | **0개** (도커 볼륨이 루트 위에 있다) |
| `DeleteOnTermination` | **`True`** |
| `TASK-MONO-630` 이 적은 절차 | 재굽기 → `ami_id` 갱신 → `terraform apply` 는 **EC2 를 교체**한다 |

⇒ **AMI 재굽기 = 인스턴스 교체 = 루트 볼륨 파괴 = 지금 DB 의 마이그레이션 이력 소멸.**

🔴🔴 그런데 아래 ③은 «postgres `V19` 가 **기존 볼륨에** 적용되는가» 다. 교체 뒤에는 V19 가
**빈 DB 의 초기 체인 일부로** 돌아가므로 순서 결함에 **영구 초록**이 된다 — 이 저장소가 이미
이름 붙인 함정 그대로다. **즉 ③은 재굽기 전에만 잴 수 있고, 지나가면 영영 못 잰다.**

### 그래서 순서가 이렇다

1. 🔴 **재굽기 전에** 지금 인스턴스를 한 번 켜서 이 티켓(과 `TASK-MONO-633`)을 수확한다.
   현재 AMI 로도 **전체 스택 기동은 정상**이다(묶음 기동만 안 된다 — `TASK-MONO-647`).
2. 그 뒤에 재굽기.

🔵 예산: 2026-09-08 UTC 실측 `379/600분`. 🔴 그 자리서 다시 재라 — 단일 표본이다.
🔵 창이 열리면 `TASK-MONO-633` 과 **같이** 처리한다. 둘 다 같은 창을 기다리고, 633 은
볼륨과 무관하지만 창을 두 번 열 이유가 없다.

# Acceptance Criteria

## AC-0 — 착수 게이트 (verify-then-act)

- [ ] 🔴 **창이 열렸는가를 먼저 확인한다.** 소유자가 다른 이유로 데모를 켰는가? 아니라면
      **STOP** — 이 티켓만을 위해 켜지 않는다. no-op 이 올바른 구현이다.
- [ ] 🔴 **항목마다 「아직 유효한가」를 다시 묻는다.** 아래 셋은 전부 «그때 안 쟀다» 이지
      «지금도 못 잰다» 가 아니다. 그 사이 코드가 바뀌었으면 재현 조건이 사라졌을 수 있다.
- [ ] 예산을 **다시 잰다**(`/status` 의 `used_minutes` / `budget_minutes`). 2026-09-08 UTC
      기준 `379/600`. 🔴 단일 표본이므로 그대로 믿지 말고 그 자리에서 읽어라.

## AC-1 — ① 만료 세션 · IAM 중단에서 공개 열람

- [ ] 만료된 세션 쿠키를 들고 공개 경로에 들어가 **열람이 유지되는지** 확인한다.
- [ ] IAM 을 내린 상태에서 같은 것을 확인한다.
- [ ] 🔴 **보호 경로가 열리면 안 된다** — 공개 열람이 유지되는 것과 보호 경로가 새는 것은
      다른 축이다. 둘 다 재라.

## AC-2 — ② `seed-fan.sh` 실제 로그인·발행

- [ ] 부팅 로그에서 새 아티스트 셋(a004–a006)의 로그인·발행 결과를 읽는다.
- [ ] 🔴 `seed_fail` 은 **소프트 실패**라 부팅을 안 죽인다 — 「부팅이 성공했다」를 「시드가
      성공했다」로 읽지 마라. **요약 줄을 직접 읽어라.**

## AC-3 — ③ postgres `V19` 를 기존 볼륨에

- [ ] 🔴 **신선 볼륨이 아니라 기존 볼륨**에서 적용되는지 확인한다. 새로 만든 볼륨은 이
      축을 못 잰다.
- [ ] 🔴🔴 **이 칸은 재굽기 전에만 잴 수 있다.** 재굽기 → `terraform apply` 는 인스턴스를
      교체하고, 루트 볼륨이 유일한 볼륨이며 `DeleteOnTermination=True` 다 ⇒ 지금 DB 의
      이력이 사라진다. 교체 뒤에는 `V19` 가 **빈 DB 의 초기 체인 일부**로 돌아가 순서
      결함에 **영구 초록**이 된다. **지나가면 영영 못 잰다.**
- [ ] 🔴 착수 시점에 **재굽기가 이미 일어났는지 먼저 확인하라**(AMI 의 `RepoCommit` 이
      `4d1a498ef` 의 자손인가). 일어났다면 이 칸은 **⚪ 로 닫고 «창을 놓쳤다» 고 적어라** —
      새 볼륨에서 초록이 나온 것을 «통과» 로 기록하면 그것이 거짓이다.
- [ ] `flyway_schema_history` 의 행을 읽어 `V19` 가 **성공으로 기록**됐는지 본다.
      🔴 파일이 있는 것과 이력 행이 있는 것은 다른 축이다.
- [ ] 실패하면 🔴 **적용된 마이그레이션을 편집하지 마라**(체크섬). 새 버전으로 고친다.

## AC-4 — 결과를 되돌려 준다

- [ ] 잰 결과를 이 티켓의 § Verification 에 적는다.
- [ ] 🔴 셋 중 하나라도 **결함이 나오면 별도 티켓**이다. 여기서 고치지 말고 기안하라 —
      이 티켓은 «재는 것» 이 일이다.
- [ ] 🔴 못 잰 항목이 남으면 **⚪ 로 «왜 못 쟀는지» 를 적어라.** 그리고 그 항목이 다시
      집을 잃지 않게 **어디로 갔는지** 적어라.

# Edge Cases

| 상황 | 기대 |
|---|---|
| 창이 안 열린다 | **STOP.** no-op 이 올바른 구현이다 |
| 창은 열렸는데 예산이 빠듯하다 | ③(기존 볼륨 `V19`)을 **먼저** 하라 — 셋 중 가장 위험하다 |
| 그 사이 코드가 바뀌어 재현 조건이 사라짐 | 그 사실을 적고 그 항목을 닫아라 |
| 셋 다 통과 | 이 티켓을 닫는다. 결함이 없다는 것도 측정이다 |

# Failure Scenarios

1. **이 티켓만을 위해 EC2 를 켠다** → 착수 게이트 위반이고 예산을 쓴다.
2. **신선 볼륨에서 `V19` 를 재고 «통과» 라 적는다** → 이 저장소가 이름 붙인 함정을 그대로
   밟는다. 신선 볼륨은 마이그레이션 순서 결함에 **영구 초록**이다.
3. **부팅 성공을 시드 성공으로 읽는다** → `seed_fail` 은 소프트 실패다.
4. **결함을 여기서 고친다** → 이 티켓은 측정이다. 고치는 것은 별도 티켓이다.
5. **못 잰 항목을 그냥 닫는다** → 지금 이 티켓이 존재하는 이유가 정확히 그것이다.

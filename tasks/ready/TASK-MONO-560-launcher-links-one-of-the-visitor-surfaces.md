# 배경 — 2026-08-19(UTC) 소유자가 직접 밟았다

기동 후 "데모 사이트 열기 →" 를 눌렀더니 404 였고(그건 **부팅 중**이라 별건이다),
그 자리에서 나온 질문이 이 티켓이다:

> *"데모사이트는 뭘 얘기하는거야? 화면보는 사이트가 이커머스, 팬, 콘솔 3개 있잖아"*

**포트폴리오 소유자 본인이 자기 데모에서 화면 두 개를 못 찾았다.** 면접관이 찾을 리 없다.

## 실측 — 링크는 정확히 하나다

`infra/demo/aws/site/index.html`:

```js
const demoHost = (ip) => `${ip.replace(/\./g, "-")}.sslip.io`;  // GUARD-T-ANCHOR
const demoUrl  = (ip) => `http://console.${demoHost(ip)}/`;     // L109
…
if (ip) $("open").href = demoUrl(ip);                            // L136
```

`<a>` 태그는 하나(`id="open"`, L57)이고 그 목적지는 **운영 콘솔뿐**이다.

Traefik 이 실제로 라우팅하는 호스트를 전수로 뽑으면 브라우저로 여는 화면은 셋이다.
같은 IP 에서 전부 200 을 확인했다(2026-08-19 12:07 UTC):

| 화면 | 호스트 | 실측 |
|---|---|---|
| 운영 콘솔 | `console.<host>/` | 200 (→ `/login?redirect=/dashboards/overview`) |
| 이커머스 스토어프런트 | `web.ecommerce.<host>/` | 200 |
| 팬 플랫폼 웹 | `web.fan-platform.<host>/` | 200 |

나머지 Host 규칙은 API 게이트웨이(`ecommerce.` `wms.` `scm.` `erp.` `finance.`
`fan-platform.` `iam.`)와 관측 도구(`grafana.iam.` `grafana.wms.` `kafka.iam.`
`kafka.wms.`) 다 — 브라우저로 "구경하는" 화면이 아니다.

## 🔴 페이지는 이미 도메인별 상태를 알고 있다

`renderDomains()` 가 도메인마다 행을 그리고 `up`/`partial` 배지와 시작/종료 버튼을
붙인다. 즉 **"이 도메인이 지금 열리는가" 를 이미 계산하고 있다.** 없는 것은 링크뿐이다.

## 🔴 그래서 링크를 그냥 박으면 안 된다

부팅에는 약 10분이 걸리고, 그 창에서 각 화면은 404 다. 안 뜬 화면에 링크를 주면
방문자는 404 를 보고 **"고장났다"** 로 읽는다 — 이번에 소유자가 겪은 것이 정확히 그
오독이다. 링크는 그 도메인이 `up` 일 때만 살아 있어야 한다.

# Goal

방문자가 **볼 수 있는 화면 전부**를, **지금 열리는 것만**, 론처에서 찾을 수 있게 한다.

# Acceptance Criteria

**AC-0 — 재확인 (verify-then-act). 🔴 목록을 물려받지 말고 다시 세라.**
착수 시점에 Traefik `Host(...)` 규칙을 **전수로** 뽑고, 그중 브라우저 화면인 것을
직접 열어 판정한다. 위 표는 2026-08-19 관측이다 — 그 사이에 늘거나 줄었을 수 있다.

🔴 **`admin.ecommerce.<host>` 를 특히 확인하라.** IAM 시드가 그 호스트를 OAuth 콜백으로
등록해 두었는데(`ecommerce-admin-dashboard-client`) **Traefik Host 규칙에는 없다.**
둘 중 하나다: (a) 라우트가 빠진 것이고 그러면 화면이 하나 더 있어야 한다, (b) 콜백이
낡은 것이다. **어느 쪽인지 확정하고 적어라.** 확정 없이 링크 3개로 넘어가면 이 티켓이
"전부 링크했다" 고 주장하면서 실제로는 하나를 빠뜨린다.

**AC-1 — 모든 방문자 화면이 론처에서 도달 가능하다.**
AC-0 이 확정한 화면 전부에 링크가 있다. 각 링크의 목적지를 **실제로 열어** 200 을 확인한다
(리다이렉트 추적 후 최종 상태 — 콘솔은 `/login` 으로 307 을 준다).

**AC-2 — 안 뜬 화면은 링크되지 않는다. 🔴 대조군 필수.**

| 칸 | 상황 | 기대 |
|---|---|---|
| (1) | 도메인 `up` | 링크 활성, 클릭 시 그 화면 |
| (2) | 도메인 `down`/`unknown` (**bite**) | 링크 **비활성** — 클릭해도 404 로 안 보낸다 |
| (3) | 도메인 `partial` (**경계**) | 어느 쪽으로 정할지 **명시하고 그대로 동작** |
| (4) | 헬스 스냅샷이 `stale` | 낡은 값으로 활성화하지 않는다 |

🔴 (4)를 빼지 마라. `health_stale` 은 TASK-MONO-551 이 만든 필드이고, 그게 참일 때
`up` 을 믿으면 **꺼진 스택의 링크를 초록으로** 준다.

**AC-3 — 호스트명은 계속 IP 에서 유도된다.**
`demoHost()` 는 재기동마다 바뀌는 IP 를 대시 표기로 바꾼다(`GUARD-T-ANCHOR`).
새 링크도 **전부 그 함수를 통과**해야 한다. 🔴 한 곳이라도 IP 를 직접 문자열로 조립하면
다음 재기동에서 그 링크만 죽고, 나머지가 멀쩡해서 **원인이 안 보인다**.

**AC-4 — 가드.**
`verify-demo-wrapper.sh` 의 기존 사이트 가드(`GUARD-T-ANCHOR` 계열) 옆에 추가한다:
- 하드코딩된 sslip 호스트 문자열이 `index.html` 에 나타나면 실패(AC-3 회귀).
- 링크 생성이 도메인 상태를 **안 보는** 모양이면 실패(AC-2 회귀).
- 🔴 대조군: 추출이 살아 있음을 증명하는 칸(알려진 다른 심볼이 보이는지).

**AC-5 — 라이브 왕복.**
실제 기동에서 **부팅 중 한 번**(링크 비활성 확인)과 **전부 up 이후 한 번**(전 링크 200
확인) 두 시점을 본다. 🔴 한 시점만 보면 AC-2 의 (1)과 (2) 중 하나가 안 행사된다.

# Edge Cases

- **`partial` 상태**: 도메인은 떴는데 일부 컨테이너가 아직이다. 프런트 컨테이너가
  그 "일부" 면 링크는 활성인데 404 다 — AC-2 (3)이 이걸 강제로 결정하게 한다.
- **`admin.ecommerce` 라우트 부재**: AC-0 이 확정한다. 라우트를 만드는 것은 이 티켓
  범위 밖이므로, (a)로 판명되면 **별도 티켓을 파일하고 이 티켓에서는 링크하지 않는다.**
- **API 게이트웨이/관측 도구를 링크할 것인가**: 지금은 안 한다. 다만 포트폴리오 관점에서
  Grafana/Kafka UI 는 보여줄 값이 있다 — 판단 근거를 적어 두고 넘어가라(나중에 "왜 뺐지"
  가 반복되지 않게).
- **콘솔의 로그인 리다이렉트**: 최종 200 이지만 첫 응답은 307 이다. 판정에 상태 코드를
  쓸 때 리다이렉트를 추적하지 않으면 "안 뜬다" 로 오독한다.

# Failure Scenarios

- **링크만 3개 박고 상태를 안 보면**: 부팅 10분 창 전체에서 방문자가 404 를 본다.
  이 티켓이 시작된 그 오독을 **두 배로** 만든다.
- **AC-0 을 건너뛰고 위 표를 그대로 쓰면**: `admin.ecommerce` 가 미해결로 남고,
  티켓은 "전부 링크됨" 을 주장한다 — 거짓 완결이다.
- **하드코딩 호스트로 링크를 만들면**: 이번 IP 에서는 전부 통과하고 **다음 재기동에서만**
  깨진다. 그때는 이 변경이 용의자로 안 떠오른다.

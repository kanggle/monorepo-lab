# 기전 — 판별자가 **자기 설명 문구**에 걸린다

`(z16)` 은 게이트 블록을 이렇게 특정한다:

```bash
z16_g="$(grep -n 'if \[ "\$LIVE" -eq 0 \]; then' "$1" | head -1 | cut -d: -f1)"
```

그런데 **이 파일에서 그 문자열의 첫 번째 등장은 게이트가 아니라 `(z16)` 자신의 주석**이다:

```
2711:# 게이트 블록 = `if [ "$LIVE" -eq 0 ]; then` 부터 열 0의 첫 `fi` 까지.   ← head -1 이 고르는 줄
2884:if [ "$LIVE" -eq 0 ]; then                                            ← 진짜 게이트
```

⇒ 추출 구간이 **2711–2753**, 즉 **`(z16)` 자신의 본문**이 된다.

## 🔴🔴 그리고 안전망이 그것을 가려 준다

`(z16)` 은 이 실패를 예상하고 안전망을 달아 뒀다 — *"구간을 제대로 집었는지 먼저 확인한다"*:

```bash
grep -q '정적 검증 PASS' "$z16_region" || { echo "__WRONGBLOCK__"; return 0; }
```

**그 술어가 통과한다.** 왜냐하면 잘못 집힌 구간이 하필 **그 문자열을 세 번 언급하는 코드**이기 때문이다:

| 줄 | 내용 |
|---|---|
| 2712 | `# 그 안에 있어도 되는 것은 "정적 검증 PASS" 와 ...` (주석) |
| 2721 | `grep -q '정적 검증 PASS' "$z16_region" ...` (자기 자신) |
| 2737 | `fail "(z16) 게이트 블록에 '정적 검증 PASS' 가 없습니다 ..."` (자기 에러 메시지) |

⇒ **파수꾼이 «내가 맞는 방을 봤나» 를 묻는데, 잘못 든 방이 그 질문의 답을 벽에 적어 둔 방이었다.**

## 🔴 bite 테스트도 같은 앵커를 쓴다 — 그래서 서로 동의한다

```bash
awk '{print} /if \[ "\$LIVE" -eq 0 \]; then/ && !d {print "  echo \"[verify] (zz9) ...\""; d=1}'
```

주입도 **첫 번째 매치**(= 같은 주석) 뒤에 한다. ⇒ 주입과 추출이 **같은 잘못된 구간**을
가리키므로 서로 일치하고, bite 는 초록으로 보고된다.
**주입기와 판정기가 같은 오류를 공유하면 대조군이 되지 못한다.**

# ✅ 실측 — 추론이 아니라 **주입으로 증명했다** (2026-09-01)

진짜 게이트 블록 **안**에 가짜 칸을 넣고 `(z16)` 을 돌렸다:

```
진짜 게이트=2884
--- 주입 확인 (게이트 블록 안) ---

  echo "[verify] (zzz1) 진짜 게이트 안에 갇힌 가짜 칸"      ← 주입됨
```

🔴 **`(z16)` 이 존재하는 이유가 정확히 이 시나리오다.** 그 docstring 이 스스로 적었다:

> *"(z15) 를 `if [ "$LIVE" -eq 0 ]` 블록 **안**에 넣었다. … 로컬에서는 6칸이 전부 물었고

> 돌린다."*

⇒ **가드는 자기가 막으려던 사건을 지금 다시 통과시킨다.**

🔵 **과대주장하지 않는다 — 이 티켓이 재지 않은 것:**

- 현재 파일에 **실제로 갇힌 칸이 있는지는 별개 질문**이다. 이 티켓은 *"가드가 못 잡는다"* 를

## AC-1 — 🔴 **지금 실제로 갇힌 칸이 있는지 따로 세라**

가드가 못 잡았다는 것과 잡을 것이 있었다는 것은 **다른 주장**이다.
열 0 앵커로 진짜 게이트 구간을 뽑아 칸 선언을 센다. **0건이면 0건이라고 적는다** —
그것은 «결함 없음» 이 아니라 «이 축에서 오늘 피해는 없었다» 이다.

## AC-2 — 고친 뒤 **주입으로** 물어야 한다

- 🔴 **주입이 실제로 됐는지 먼저 단언**하라(안 물린 것과 안 넣어진 것은 구별돼야 한다).
- 진짜 게이트 안에 칸을 주입 → `(z16)` 이 **FAIL**.
- 게이트 **위**(정적 구간)에 같은 칸을 두면 → **PASS**. 🔵 **두 방향 다** 확인해야 한다.
- 🔴 **음성 대조군**: 앵커만 고치고 bite 하네스를 안 고친 판본에서는 여전히 **안 물어야** 한다
  (그래야 «둘 다 고쳐야 한다» 가 실측이 된다).

## AC-3 — 같은 모양이 이 파일에 또 있는지 **센다**

이 파일에는 자기 자신을 읽는 칸이 여럿이다(`z2` · `z16` …). 각각이 **리터럴 패턴으로 자기
소스를 grep** 하는지 세고, 그 패턴이 **자기 주석/에러 메시지에도 매치되는지** 표로 적는다.
🔴 **고치는 것은 이 티켓 범위 밖**이다 — 세고, 필요하면 후속 티켓을 판다.

## AC-4 — 이 결함이 **안 고치는 것**을 적는다

- 이 수리는 «갇힌 칸» 축만 본다. 칸이 **게이트 위에 있는데도 안 도는** 다른 경로
  (조건부 `skip`, 이른 `exit`)는 이 가드의 축이 아니다.
- `TASK-MONO-606` 의 `(z18)`/`(z18s)` 배치는 **이 티켓과 무관하게 이미 옳다** — 다만
  이 티켓이 닫히기 전까지 **그것을 강제하는 것은 아무것도 없다.**

215줄에 `command -v` 선언이 0건**이라 두 경계 모두 `node` 하나를 뽑는다.

⇒ **결함은 실재하지만 오늘 잠복**이다. 🔴 그 215줄 안에 누가 `command -v` 를 하나 추가하면
`(z2)` 는 그것을 **조용히 놓치고**, packer 는 이미지를 다 구운 뒤 **20분째 7단계에서 죽는다**
(이 파일이 기록한 2026-08-17 의 그 실패다). ⇒ **`TASK-MONO-609`** 로 판다(수정은 이 티켓 범위 밖).

## 🔵 부수 발견 — FAIL 메시지의 백틱이 **실행**되고 있었다

`(z16)` 의 안내 문구가 이렇게 나오고 있었다:

```
bash: command substitution: line 2: syntax error: unexpected end of file
→ 게이트() **위쪽** 정적 구간으로 옮기세요.
```

큰따옴표 안의 백틱이 **명령 치환**이라 `if [ "$LIVE" -eq 0 ]` 를 실행하려다 죽고, 그 자리가
빈 문자열이 된다. 🔴 **이 가드가 처음으로 발화할 수 있게 된 바로 그 커밋에서, 발화할 때 읽히는
문장이 깨져 있었다.** 이스케이프해 고쳤다(형제 grep = 이 파일에 같은 모양 **0건**, 단발이다).

# 배경 — 규율은 있는데 그것을 **재는 단계**가 없다

`MEMORY.md` 는 매 세션 자동 로드되므로 크기가 곧 **토큰 비용**이고, 그래서 한도가 있다.
그런데 그 한도를 **아무것도 검사하지 않는다**:

| | |
|---|---|
| 한도의 출처 | `MEMORY.md` 헤더 + `feedback_memory_index_one_line_discipline` (사람이 읽는 규율) |
| 검사 주체 | **없음** |
| `/audit-memory` 가 보는 것 | Phase 2-1 stale · 2-2 모순 · 2-3 댕글링 · 2-4 CLAUDE.md 중복 · 2-5 승격 후보 — **크기는 안 봄** |
| 리포 CI | 🔴 불가 — `MEMORY.md` 는 `~/.claude/projects/<slug>/memory/` 에 있어 **리포 밖**이다 |
| 훅 | 🔴 `.claude/hooks/` + `settings.json` 은 분류기 하드블록(에이전트가 못 씀) |

⇒ 자동 강제가 가능한 자리는 훅뿐인데 막혀 있고, 남는 유일한 실행 가능 지점이
**`/audit-memory` 라는 사람이 부르는 명령**이다.

## 재발 이력 (3회, 전부 사람이 발견)

- **2026-06-06** — audit-memory 도중 우연히 24.4KB 초과 적발
- **2026-08-08** — 25.6KB 적발 → 16줄 압축 → 23.6KB. **같은 날 오후 24,432B 로 복귀**
- **2026-08-14** — 다시 초과. 🔴 이때 **2026-08-09 에 이미 적어 둔 처방**(*"또 압축하지 말고
  구조를 바꿔라"*)을 읽기 전에 또 압축부터 했고, 성과는 **188B(0.8%)** 였다

⇒ 규율 문장은 *"압축해라"* 까지만 전달하고 *"이미 두 번 해봤고 안 통한다"* 는 못 전달한다.
**실측 상수**가 명령 안에 있어야 다음 사람(대개 나)이 재실험하지 않는다.

## 실측 상수 (2026-08-14 — 이 티켓이 서 있는 근거)

```
포인터당 120B  ·  그중 43%가 파일명(= 주소라 압축 불가)
⇒ 24KB 한도 = 포인터 약 200개의 다른 이름
줄 병합 실측: 6줄 합쳐 188B(0.8%)  ⇒ 바이트는 '줄'이 아니라 '포인터'에 붙는다
```

이번 회차에 3단 lazy-load 로 구조를 바꿔 `MEMORY.md` 22,162B(여유 9.8%) · 포인터 170 ·
`PLAYBOOKS.md` 신설(38) · `ARCHIVE.md`(71) 로 정리했고, **포인터 집합 202→202 손실 0** 으로
검증했다. 이 티켓은 그 상태를 **유지시키는 계측기**를 명령에 넣는 일이다.

# Edge Cases

- **메모리 디렉터리는 리포 밖이다** — 명령은 절대경로가 아니라
  *"현재 프로젝트의 memory 디렉터리"* 로 지시해야 다른 머신/다른 프로젝트에서도 성립한다
- **정원 숫자 자체가 드리프트한다** — 파일명이 길어지면 포인터당 바이트가 올라간다.
  명령은 정원을 상수로 박기보다 **재측정 방법**(포인터당 바이트를 그 자리서 계산)을 적어야 한다
- `ARCHIVE.md` 에 **의도된 중복** 2건이 있다(작업은 끝났어도 함정은 산다) — 감사에서
  재지적하지 말 것이 이미 규율에 적혀 있다

# Failure Scenarios

- **바이트만 재고 포인터를 안 센다** → *"압축하면 되겠네"* 로 오도된다. 실측 0.8% 라
  압축은 답이 아니었다. 1차 지표가 포인터여야 하는 이유가 이것이다
- **초과 지시가 "압축"에서 멈춘다** → 2026-08-08 처럼 한 세션이 그 여유를 도로 먹는다.
  압축은 **이벤트**고 성장은 **프로세스**다
- **함정 섹션을 lazy-load 로 내린다** → 크기는 줄지만 **안 로드된 함정을 다시 밟는다.**
  이건 개선이 아니라 사고다
- **AC-3 없이 닫는다** → 술어만 있고 발화하지 않는 단계가 남는다. 이 저장소가
  `TASK-MONO-518`/`524` 에서 두 번 밟은 모양이다

# Context — 실측 (2026-08-27 UTC, `origin/main` = `91deefcc8`)

## ① 임계에 유도가 없다 — 훅이 스스로 그렇게 적어 뒀다

```powershell
$QuotaPointers  = 180     # 24576 ÷ 포인터당바이트(실측 130) = 189, 여유 두고 180
$HardLimitBytes = 24576   # 24KB — 참고용(보고에만 사용, 판정은 포인터로 한다)
```

🔴 **그 나눗셈은 단위가 섞여 있다** — 분자 `24576` 은 **문자** 한도로 들여온 값이고
분모 `130` 은 **바이트**다. 서로 다른 단위를 나눈 몫이 임계가 됐다.
이 사실은 이미 `TASK-MONO-595` 가 커맨드 쪽에서 다루고 있고, 메모리
`feedback_memory_index_one_line_discipline` 이 *"정원 180 자체가 철회된 산술의 산물이다 —
임계값에 유효한 근거가 없다"* 로 기록해 두었다.

## ② 🔴🔴 그리고 그 산식의 **입력값이 낡았다** — 130 → **157 (+21%)**

`MEMORY.md` 실측(2026-08-27, 이 티켓 기안 시점):

```
자 20,078 · 바이트 28,180 · narrow 포인터 179
포인터당 바이트 = 28,180 ÷ 179 = 157      ← 훅 주석의 "실측 130" 이 낡았다
```

**훅 자신의 산식을 지금 입력으로 다시 돌리면**: `24576 ÷ 157 = 156.5` ⇒ 「여유 두고」 원칙까지
적용하면 정원은 **약 150** 이 되고, 현재 **179 는 이미 초과**다.

⇒ **같은 공식, 같은 파일, 반대 판정.** 임계가 «지켜지고 있다» 는 상태는 공식이 틀렸기 때문에
성립한 것이지 파일이 작아서가 아니다. 🔴 이것이 정확히 *"게이트 없는 숫자는 반드시 낡는다"*
의 사례이고, **낡은 쪽이 게이트 자신의 상수**라는 점에서 더 나쁘다.

# Acceptance Criteria

## AC-0 — **두 게이트를 다시 재고, 이 티켓의 숫자를 상속하지 마라**

위 표는 2026-08-27 값이고 `MEMORY.md` 는 세션마다 바뀐다. 착수 시점에:

1. 훅 소스에서 `$QuotaPointers` · `$HardLimitBytes` · 판정식 · **정규식 리터럴**을 읽는다.
   🔴 정규식이 `[a-z0-9_]+` 인지 확인 — 이게 좁아서 하이픈·대문자·`ARCHIVE.md` 를 안 센다.
   **정원을 논하기 전에 세는 것부터 옳은지 정해야 한다**(AC-1 의 입력이다).
2. `MEMORY.md` 실측: 자 · 바이트 · narrow ptr · wide ptr · 경로 자 · 산문 자.
3. **포인터당 바이트를 다시 구한다** — ②의 157 이 그대로인지, 또 움직였는지.
   🔵 움직였다면 그 자체가 AC-1 의 근거가 된다(**입력이 흐르는 값이면 그 몫을 상수로 얼리면 안 된다**).

## AC-1 — 🔴🔴 **판정축을 먼저 정한다. 숫자는 그 다음이다**

최소 세 안을 놓고 각각 **무엇을 보호하는지**와 **오작동 방향**을 적는다:

- **A. 포인터 개수 유지, 임계만 재도출** — 유도를 어디서 가져올 것인가가 문제다.
  🔴 `문자한도 ÷ 포인터당바이트` 는 ②가 보였듯 **입력이 흐른다**. 흐르는 입력에서 상수를 뽑으면
  같은 드리프트가 재발한다.
- **B. 문자 수로 전환** — 하네스 게이트와 **같은 것**을 재게 된다.
  🔵 장점: 토큰 비용이라는 실제 축을 직접 잰다. 🔴 단점: 하네스가 이미 그걸 재므로 **중복 게이트**가
  되고, 리포 훅의 존재 이유(하네스보다 **먼저·리포 규칙으로** 잡는다)가 약해진다.
- **C. 둘 다 재되 판정은 하나** — 보고는 두 축, 발화는 정한 축.
  🔴 그러면 «어느 축으로 발화했나» 를 메시지가 **반드시** 말해야 한다.

🔴 **어느 안이든 임계에 유도를 붙여라.** 유도 없는 숫자는 이 파일이 이미 두 번 낳았다.
🔵 **유도가 안 나오면 그것도 산출물이다** — *"근거를 못 찾았고 값 N 은 관측 M 에서 온 임의값"*
이라고 **훅 주석에 정직하게** 적는 것이, 가짜 나눗셈을 적는 것보다 낫다.

## AC-2 — 새 임계를 **자기 유도와 함께** 훅에 적는다

주석이 답해야 하는 것: ⑴ 이 수는 무엇에서 나왔나 ⑵ **무엇이 바뀌면 다시 재야 하나**
⑶ 재는 방법(명령 한 줄). ⑶ 이 없으면 다음 사람도 «실측 130» 처럼 검증 불가한 숫자를 물려받는다.

🔵 재측정 트리거를 **숫자로** 적어라 — *"포인터당 바이트가 ±15% 넘게 변하면"* 같은 형태.
막연한 *"주기적으로"* 는 아무도 안 한다.

## AC-3 — 🔴 **발화 메시지의 REMEDIATION 이 실재 재고를 반영해야 한다**

③에서 봤듯 ①ARCHIVE ②PLAYBOOKS 는 **재고 0** 이다. 지금 발화하면 훅은
**실행 불가능한 두 선택지를 먼저 제시**한다. 최소한:

- 후보 계산이 **0을 내면 «없음» 이라고 말한다**(현재 코드는 `$candText` 폴백이 있으나
  ①ARCHIVE 쪽에는 후보 계산 자체가 없다 — 🔴 **확인하고, 없으면 그것도 적어라**).
- 🔵 형제 통합(④)을 선택지로 **넣을지 말지 정한다** — 넣는다면 «함정 포인터를 빼는 일이라
  소유자 결정» 이라는 단서를 같이 넣어야 오작동하지 않는다.

## AC-4 — **bite 로 양방향 증명**

임계 **바로 아래**에서 미발화 · **바로 위**에서 발화. 🔴 한쪽만 보면 «항상 조용한 훅» 과
구별되지 않는다([[feedback_why_a_guard_does_not_bite]]).
🔴🔴 **주입 착지부터 단언하라** — bite 픽스처가 실제로 그 포인터 수를 만들었는지 먼저 세고,

# Edge Cases

- **`MEMORY.md` 가 착수 시점에 이미 180 초과** → 정원을 «맞추려고» 올리지 마라.
  🔴 그건 유도가 아니라 **현재값에 임계를 맞추는 것**이고, 그러면 게이트가 아무것도 안 잰다.
  유도가 먼저 나오고 현재값이 그 위면 **초과 상태로 정직하게 보고**한다.
- **정규식을 넓히면 포인터 수가 뛴다** — 2026-08-23 실측 184 vs 189, 현재 narrow 179 / wide 184.
  🔴 축을 넓히면서 임계를 그대로 두면 **이유 없이 발화**한다. 둘은 **같은 커밋**에서 바뀌어야 한다.
- **하네스 문자 한도를 못 관측** → 발화 문구가 유일한 출처다. 못 봤으면 **«미관측»** 으로 적고
  추정치를 상수로 쓰지 마라.
- **`.claude/hooks/` 분류기** → 🔴 이 편집은 훅 **로직**이라 권한 편집은 아니지만, hooks 경로는
  과거 하드블록 이력이 있고 2026-08-14 에 **통과 실증**도 있다. **먼저 시도**하고 실제 차단 시에만
  패치를 사용자에게 넘긴다([[env_classifier_false_block_map]]).

# Failure Scenarios

- **숫자만 바꾸고 유도를 안 적는다** → 다음 감사에서 «이 180 은 어디서 왔나» 를 또 묻게 되고,
  이번엔 **세 번째** 유도 없는 상수가 된다.
- **흐르는 입력에서 상수를 뽑는다**(`24576 ÷ 포인터당바이트`) → ②가 보인 드리프트가 그대로 재발.
  포인터당 바이트는 **항목이 늘수록 오르는 값**이라 상수의 재료로 부적절하다.
- **bite 를 디바운스 마커 없이 돌린다** → 발화해야 할 케이스가 조용히 통과하고
  **«고쳤다» 가 초록으로 보고**된다. AC-4 가 이걸 지명한 이유다.
- **worktree 에서 «안 먹네» 로 결론** → 도는 것은 메인 체크아웃 사본이다. 두 사본을 대조하지 않으면
  **엉뚱한 파일을 고치고 고쳤다고 보고**하게 된다.
- **595 와 나눠 머지하고 한쪽만 고친다** → 훅의 값과 커맨드의 서술이 갈라진다.
  이 저장소가 이름 붙인 그 실패형이 **이 티켓 자신의 주제 위에서** 재발하는 모양이다.

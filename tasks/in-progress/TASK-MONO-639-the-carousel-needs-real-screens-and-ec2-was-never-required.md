# Acceptance Criteria

## AC-0 — 착수 전 실측 (verify-then-act)

- [ ] 🔴🔴 **`TASK-MONO-638` 이 머지됐는지 먼저 확인한다.** 데이터가 얇은 채로 찍으면
      캐러셀이 **오늘의 빈 화면을 영구히 박제**한다. 안 됐으면 그때까지 이 티켓을 시작하지
      마라(no-op 이 올바른 구현이다).
- [ ] 세 주소를 **다시 찔러** 200 인지, SSR 에 실제 값이 실려 있는지 적는다. 🔴 콘솔은
      클라이언트 렌더라 **HTML 로 판정되지 않는다** — 그 축은 브라우저로만 잰다.
- [ ] `fan-platform-web` 에 Playwright 가 있는지 **세어서** 적는다(위 Context 의 미측정 항목).

## AC-1 — 진짜 화면을 찍는다

- [ ] 앱마다 **주요 페이지 3~5장**을 찍는다. 무엇이 「주요」인지 **먼저 목록으로 정하고
      근거를 적는다**(방문자가 이 제품을 이해하는 데 필요한 화면이 무엇인가).
- [ ] 🔴🔴 **가짜 화면을 만들지 마라**(`TASK-MONO-634` AC-6 의 금지). 목업·합성·손으로 그린
      스크린샷은 전부 이 AC 를 못 닫는다. 찍은 것은 **그 주소가 그 순간 실제로 준 화면**이어야
      한다.
- [ ] 캡처마다 **어느 URL 을 언제 찍었는지** 기록이 남는다(파일명 또는 매니페스트).
      🔴 기록이 없으면 다음 사람이 «이게 아직 맞는 화면인가» 를 판정할 방법이 없다.
- [ ] 로그인·개인정보가 화면에 없다 — 공개 열람 경로만 찍으므로 원래 없어야 하지만,
      **찍고 나서 눈으로 확인**한다(허용 목록을 믿지 말고 산출물을 봐라).

## AC-2 — 다시 만들 수 있다

- [ ] 캡처를 **재생성하는 스크립트**가 저장소에 있다. 한 번 돌리면 같은 목록을 다시 찍는다.
- [ ] 스크립트를 **어디에 둘지 정하고 근거를 적는다** — 기존 Playwright 설정을 재사용할지
      (`web-store`/`console-web` 의 것), `infra/demo/` 아래 독립으로 둘지. 🔴 세 앱을 걸치는
      일인데 한 앱의 설정에 얹으면 나머지 둘이 그 앱의 사정에 묶인다.
- [ ] 🔴 스크립트가 **네트워크 없이도 실패를 정직하게 말한다** — 주소가 죽었으면 «캡처
      실패» 로 죽고, 빈 이미지나 옛 이미지를 남기지 않는다.
- [ ] 뷰포트·스케일을 고정한다. 안 그러면 재생성마다 이미지가 달라져 diff 가 무의미해진다.

## AC-3 — 페이지가 무거워지지 않는다

- [ ] 이미지 **총 용량 예산을 정하고 실측**한다(장수 × 장당 크기). 🔴 숫자를 적어라 —
      「최적화했다」는 측정이 아니다.
- [ ] 캐러셀 첫 장 외에는 **지연 로드**된다(`loading="lazy"` 는 이미 쓰고 있다).
- [ ] 🟢 론처는 정적 `<img>` 라 Vercel 이미지 변환 할당량을 **안 탄다** — 확인하고 적는다
      (`TASK-MONO-587` 의 축과 이 티켓이 무관하다는 것을 기록으로 남긴다).

## AC-4 — 가드

- [ ] `build.sh` 가 찍는 「썸네일 N 장 포함」이 **기대한 장수와 같은지** 무는 칸을 둔다.
      🔴 0장이어도 빌드는 성공한다(오늘이 그렇다) — 그래서 «있어야 하는데 없다» 를 아무도
      말해 주지 않는다.
- [ ] 마크업이 참조하는 이미지가 **전부 실재하는지** 대조한다(참조 ↔ 파일 양방향).
      한쪽만 보면 «파일은 있는데 아무도 안 그린다» 또는 그 반대가 조용히 통과한다.
- [ ] 하한을 둘지는 **모집단이 늘어나는지 줄어드는지 세어 보고** 정한다(줄어드는 모집단에
      하한을 걸면 성공이 고장난다 — 이 저장소가 반복해서 밟은 함정).
- [ ] **bite**: 이미지 하나를 지우거나 마크업 참조를 하나 바꾸면 그 가드가 빨개진다.

# Failure Scenarios

1. **데이터 확충 전에 찍는다** → 상품 8개·아티스트 3명짜리 빈 화면이 포트폴리오 첫 화면에
   영구히 박힌다. 그리고 그 이미지는 «이 제품은 이 정도다» 라고 말한다.
2. **손으로 한 번 찍고 끝낸다** → 화면이 바뀌는 날 이미지가 조용히 낡는다. 낡음을 알려 주는
   것이 아무것도 없다.
3. **목업을 만든다** → `TASK-MONO-634` AC-6 이 명시적으로 금지한 것이다. 그리고 포트폴리오의
   화면이 실제 제품과 다르다는 것은 이 저장소가 고치려는 결함 그 자체다.
4. **EC2 를 켠다** → 필요 없는데 예산을 쓴다. 필요하다고 느껴지면 전제가 틀린 것이므로
   멈추고 다시 재라.

# ⏳ 선행 — 없음. 그러나 **결정 티켓이 아니다**

이 티켓은 *"프리뷰를 끄자"* 를 **결정하지 않는다.** 레버가 **작동하는지**만 잰다.
채택 여부는 `ADR-MONO-067` 의 후속 결정이고 **소유자 사안**이다(프리뷰 URL 을 잃는 대가가 있다).

# Goal

`vercel.json` 의 `git.deploymentEnabled` 로 비프로덕션 브랜치의 배포를 끄면,
**배포가 «생성» 되지 않는지**(= 일일 한도를 소비하지 않는지) 실측한다.

---

# Context — 왜 이것만 남았나 (`TASK-MONO-575`, 2026-08-27)

575 가 **AC-2 = 「못 견딘다」** 로 닫혔다. 막는 축은 **일일 배포 수** 하나다:

| | 값 |
|---|---|
| 계정 한도 | **100 / 롤링 24h** — 🔴 **프로젝트별이 아니라 계정 전체**(프로젝트들이 나눠 쓴다) |
| 실측 소비 | **74 생성배포 / 24h @ 프로젝트 2개**(하한) |
| 프로젝트 4개 환산 | **≈148 vs 100** |

🔴🔴 **그리고 `ignoreCommand` 는 이 축을 한 건도 못 줄인다.** 창 안 생성배포 74건 중
**69건이 `Canceled by Ignored Build Step`** 이었고 실제 빌드는 **5건**뿐이었다.
limiter 는 배포 **«생성»** 을 재고, ignore 스텝은 그 **뒤** 빌드 컨테이너 안에서 돈다.

⇒ 575 가 열어 둔 선택지 중 ③(*"`ignoreCommand` 를 더 촘촘하게"*)은 **죽었다.**
남은 것은 ① 유료 플랜 ② 프로젝트 수를 안 늘리는 배치 ④ **프리뷰 배포 끄기**.
**④ 만이 저장소 안에서 할 수 있는 일**이고, 그래서 이 티켓이 그것부터 잰다.

🔵 **크기**: 창 안 생성배포 74건 중 **40건(54%)이 PR 브랜치**였다.
프리뷰가 정말 안 만들어진다면 2개 기준 **34/일**, 4개 기준 **≈68/일** ⇒ **한도 아래**.

🔴 **이 숫자는 「끄면 이렇게 된다」의 산술이지 측정이 아니다.** 그래서 AC-1 이 필요하다.

# Acceptance Criteria

## AC-0 — 착수 시 **다시 읽는다** (verify-then-act)

1. 🔴 **한도가 안 걸려 있는지 먼저 확인한다.** 걸려 있으면 이 실험은 **판정 불가**다 —
   rate limit 은 «생성 거부» 로 나타나고, 그것이 **«끄기 때문에 안 생김» 과 같은 출력**을 낸다.
   확인 = 최근 커밋의 Vercel 상태가 `rate limited` 가 아닐 것.
2. `vercel.json` 이 여전히 **2개**인지 센다(575 의 산술이 2개 기준이다).

## AC-1 — 🔴🔴 **한 프로젝트만 끈다. 다른 하나가 대조군이다.**

이것이 이 티켓의 설계 핵심이다. **같은 푸시**에서 두 프로젝트를 비교한다:

| 프로젝트 | 설정 | 기대 |
|---|---|---|
| `kanggle-fan` | `git.deploymentEnabled: { main: true }` (그 외 브랜치 off) | **커밋 상태가 아예 안 붙는다** |
| `kanggle-portfolio` | **안 건드린다** | `Canceled by Ignored Build Step` 이 **붙는다** |

🔴🔴 **둘 다 끄면 안 된다.** 상태가 둘 다 없을 때 *"안 만들어졌다"* 와 *"GitHub 연동이
멎었다"* · *"아직 안 왔다"* 가 **구별되지 않는다**. 대조군이 붙어야 «이 푸시는 Vercel 에
도달했다」가 증명되고, 그때만 상대의 **부재**가 의미를 갖는다.
[[env_empty_detector_output_is_not_absence]] [[feedback_absence_verdict_from_a_proxy_is_not_a_measurement]]
[[feedback_control_group_design_four_axes]]

**절차**: 위 설정으로 브랜치 하나를 푸시하고, **최소 90초** 기다린 뒤
`repos/:owner/:repo/commits/<sha>/status` 를 읽어 **context 목록**을 본다.

🔵 **부재는 시간축으로도 확인한다** — 대조군 상태가 도착한 **뒤에도** 상대가 없어야 한다.
대조군보다 먼저 읽으면 «아직 안 왔다» 를 «없다» 로 오독한다.

## AC-2 — 🔴 **프로덕션은 여전히 배포돼야 한다**

프리뷰를 끄는 것이 **main 배포까지 죽이면** 이 레버는 못 쓴다.
그 브랜치를 머지한 뒤 `main` 커밋에서 `kanggle-fan` 상태가 **정상으로 붙는지** 확인한다.

🔴 **이 칸을 빼지 마라.** AC-1 만 초록이면 *"배포가 통째로 멎었다"* 도 **성공으로 보인다**.

## AC-3 — 소비 감소를 **숫자로** 환산한다

AC-1·2 가 참이면 575 의 표를 다시 계산한다:

- 프로젝트 2개 기준 하루 생성배포
- 프로젝트 4개 환산 → **100 아래인가**

🔴 **575 의 하한 성질을 물려받는다** — 미머지 PR push·force-push 로 갈린 head·수동
Redeploy 는 여전히 못 센다. **«한도 아래» 를 여유로 읽지 마라.**

## AC-4 — 잃는 것을 **적는다** (채택 결정의 입력)

프리뷰 배포가 사라지면 무엇이 없어지는지 센다:

- PR 의 프리뷰 URL (리뷰어가 화면을 눈으로 보던 경로)
- `Vercel Preview Comments` 체크
- 🔴 **프리뷰에서만 잡히던 결함이 있었는지** — 있었다면 그 방어를 어디로 옮길지도 적는다

🔵 이 저장소는 프런트 e2e 를 `nightly-e2e.yml` 에 두고 있어 **머지 시점에 화면을 안 본다**
(`TASK-FAN-FE-018` 이 같은 구멍의 다른 얼굴이다). 프리뷰를 끄면 그 공백이 **커진다.**

## AC-5 — 🔴 **되돌릴 수 있게 남긴다**

판정이 «작동한다» 여도 **채택은 이 티켓이 안 한다.** 실험 설정은
**되돌리거나**, 채택 결정이 날 때까지 **명시적으로 실험임을 파일에 적어** 둔다.
🔴 실험 설정이 조용히 영구 설정이 되는 것이 이 티켓의 가장 큰 실패 모드다.

## AC-6 — 결과를 `TASK-MONO-575` 가 아니라 **`ADR-MONO-067` 후속 절**에 적는다

575 는 `done/` 이라 **동결**이다(훅이 막는다). ADR 의 AC-0 ④ 절에 이어 적는다.

# Edge Cases

| 케이스 | 처리 |
|---|---|
| `git.deploymentEnabled` 가 `vercel.json` 에서 안 먹고 **대시보드 설정에만** 있다 | 🔵 그 자체가 판정이다 — «저장소 안에서 할 수 있는 일이 아니다» 로 적고 소유자 결정으로 올린다 |
| 착수 시 rate limit 이 걸려 있다 | **판정 불가.** AC-0 ① 이 먼저 막는다 |
| 대조군에도 상태가 안 붙는다 | 🔴 **실험이 무효다** — 푸시가 Vercel 에 도달했는지부터 의심하라. 재시도 전에 원인을 적는다 |
| 상태는 안 붙는데 Vercel 대시보드엔 배포가 보인다 | 🔴 **커밋 상태 부재 ≠ 배포 부재.** 그러면 이 계측기가 틀린 것이고, 그것이 발견이다 |
| main 배포도 같이 죽는다 | AC-2 가 잡는다. **즉시 되돌린다** — 론처가 낡은 판을 서빙하게 된다 |

# 🔴 왜 이렇게 썼나 — 의도는 옳았고 구현이 환경에 묶였다

그 단언은 **빈 모집단 방지**다. 대조에 쓸 커밋이 없으면 판정이 공허해지므로 통과시키면 안
된다 — 그 판단 자체는 맞다(`feedback_non_vacuity_floor_under_draining_population` 부류).

🔴 틀린 것은 **모집단을 저장소 이력에서 가져온 것**이다. 술어는
「이 스크립트가 조상/비조상/모름을 옳게 답하는가」이고, 그 질문에 답하는 데 **이 저장소의
이력이 필요하지 않다.** 필요한 것은 «조상 관계를 가진 커밋 두 개» 뿐이고, 그건 **만들 수 있다.**

# 🟢 구현 (2026-09-10 UTC · `in-progress`)

## AC-0 — 재현했다. 가정이 아니다

`git clone --depth 1 --branch main https://github.com/kanggle/monorepo-lab.git` 로
**진짜 얕은 클론**을 만들어 확인했다:

```
rev-list --count HEAD   →  1
cat-file -e 9f0fcd2d6   →  없음
bash infra/demo/verify-demo-wrapper.sh
  →  rc=1
  →  FAIL: (z40) 대조에 쓸 커밋 9f0fcd2d6 가 이 클론에 없습니다 — 판정이 공허해집니다(얕은 클론?).
```

🔵 **nightly 로그와 글자 하나까지 같은 메시지**다 ⇒ 원인 진술이 맞다.
🔴 첫 시도는 `git clone --depth 1 file://…` 였는데 `fatal: early EOF` 로 **클론 자체가 실패**했고,
그 뒤 `cat-file` 이 「없다」를 내서 **재현으로 읽을 뻔했다.** 클론 실패와 얕은 클론은 다르다 —
그래서 `rev-list --count` 로 **클론이 성립했는지 먼저** 단언했다.

## AC-1 — 판정 행렬을 자기 완결로

임시 디렉터리에 `git init` 으로 저장소를 만들고 **`base → feature → later`** 세 커밋을
세운다. `feature` 를 임계값으로 주면 조상 관계가 **구성된 것**이므로 어떤 클론에서도 성립한다.

| 칸 | 입력 | 기대 |
|---|---|---|
| 경계값 | `feature` 자신 | `yes` · rc=0 |
| 구세대 | `base` | `no` · rc=1 |
| 🔵 신세대(새로 더함) | `later` | `yes` · rc=0 |
| 없는 커밋 | `deadbeef…` | `unknown` · rc=2 |
| 핀 결손 | `REPO_COMMIT` 없음 | `unknown` · rc=2 |

- 🔴 임계값 주입은 스크립트에 **`AMI_BUNDLE_MIN_COMMIT` override** 를 더해서 한다.
  운영 경로는 그것을 **안 쓴다**(기본값이 `9f0fcd2d6`).
- 🔴 **세 커밋이 서로 다르고 전부 채워졌는지 먼저 단언한다** — 빈 값끼리는 **서로 같아서**
  대조가 통째로 공허해진다.
- 🔴 임시 저장소를 **못 만들면 FAIL** 이다. 「못 만들었으니 통과」는 공허한 초록이고,
  그건 도구 부재이지 얕은 클론이 아니다(Edge Cases).
- 🔴 `--json` 이 다섯 상태 전부 `rc=0` 이어야 한다는 단언은 **그대로 유지**했다.

## AC-2 — 실제 핀 대조는 조건부, 그러나 조용하지 않게

```
이력 있음  →  실제 대조를 한다
이력 없음  →  skip: (z40) 실제 핀 대조 — 구운 커밋 … 이 이 클론에 없습니다(얕은 클론).
              판정 행렬은 위에서 전부 돌았습니다 — 이 skip 은 «안 쟀다» 이지 «통과» 가 아닙니다.
```

🔴 `ok:` 로 적지 않았다. 안 잰 것을 통과로 적는 것이 이 저장소의 최다 재발 결함이다.
🔵 그리고 이 대조를 **없애지 않았다** — 자기 완결 칸은 «스크립트가 옳은가» 만 재고,
«배포된 AMI 가 실제로 어느 쪽인가» 는 실제 핀으로만 알 수 있다(Failure 5).

## AC-3 — 증명: **두 방향 다 재현한 조건에서**

| 클론 | 수정 전 | 수정 후 |
|---|---|---|
| **얕음**(`--depth 1` · nightly·packer 와 같은 조건) | 🔴 `rc=1` · nightly 와 **글자까지 같은 FAIL** | 🟢 **전체 스위트 `rc=0`** · 5상태 행렬 전부 실행 · 실제 핀만 `skip:` |
| **깊음**(로컬 워크트리 · `ci.yml` 과 같은 조건) | — | 🟢 **전체 스위트 `rc=0`** · **실제 핀 = `yes`**(skip 아님, 실제로 대조) |

🔵 **두 실행처의 출력 차이가 설계 그대로다** — 같은 칸이 얕은 곳에서는 `실제 핀 = skip(얕은클론)`,
깊은 곳에서는 `실제 핀 = yes` 로 요약된다. 🔴 즉 **초록의 의미가 다르다는 것이 출력에 드러난다.**

**bite 는 셋 다 살아 있다** — 자기 완결로 바꾼 뒤에도 `(z40)` 의 `ok:` 줄이
*"bite 3칸(임계 무력화 · 모르면 허용 · 거절을 뒤로 이동)"* 을 계속 보고한다.
🔴 그리고 그 셋이 **얕은 클론에서도 돌았다**(위 `rc=0` 은 bite 를 통과한 뒤의 값이다) —
bite-1 을 `$ROOT` 가 아니라 **임시 이력**에 물린 것이 그 이유다. `$ROOT` 로 두었으면
얕은 곳에서 bite 가 조용히 죽고, 그때 이 칸은 **영원히 초록**이 됐을 것이다(Failure 3).

`LF will be replaced by CRLF` 경고가 가드 출력에 섞이면 다음 사람이 «무언가 잘못됐다» 로 읽는다.

# Edge Cases

| 상황 | 기대 |
|---|---|
| 얕은 클론(packer · nightly) | 자기 완결 칸은 **전부 돈다** · 실제 핀 대조만 `skip:` |
| 깊은 클론(로컬 · fetch-depth 0) | 전부 돈다 · 실제 핀 대조가 **실제로** 돈다 |
| git 이 아예 없는 트리 | 자기 완결 칸이 저장소를 못 만든다 ⇒ 🔴 그건 **FAIL 이 맞다**(도구 부재는 얕은 클론과 다르다) |
| 임시 저장소 생성 실패(디스크·권한) | 🔴 FAIL. 「못 만들었으니 통과」는 공허한 초록이다 |
| 임계 커밋이 나중에 rebase 로 사라진다 | 자기 완결 칸은 영향 없음 · 실제 핀 대조만 skip 으로 떨어진다 |

# Failure Scenarios

1. 🔴🔴 **`nightly-e2e.yml` 에 `fetch-depth: 0` 만 더하고 닫는다.** nightly 는 초록이 되고
   **packer 는 여전히 죽는다** — 그리고 그 사실은 **재굽기를 누르는 날에만** 드러난다(55분).
2. 🔴🔴 **커밋이 없으면 그냥 건너뛰게 고친다.** 얕은 클론에서 이 칸은 **영원히 초록**이 되고,
   그게 이 저장소에서 가장 자주 데인 모양이다(스킵이 초록으로 보고된다).
3. 🔴 **자기 완결로 바꾸면서 bite 를 안 따라 옮긴다.** 행렬은 도는데 무는 것은 없어진다.
4. **임시 저장소를 만들고 안 지운다** — 러너에 쓰레기가 쌓이고, 다음 실행의 모집단을 오염시킨다.
5. 🔴 **실제 핀 대조를 통째로 없앤다.** 그러면 「배포된 AMI 가 실제로 어느 쪽인가」를 아무도
   안 재게 된다 — 자기 완결 칸은 **스크립트가 옳은가**만 재지 **배포가 옳은가**는 안 잰다.

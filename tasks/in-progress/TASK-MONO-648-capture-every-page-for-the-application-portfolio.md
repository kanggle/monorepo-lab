⇒ 이 둘을 모르면 스크립트는 **로그인 화면과 거절 화면을 찍고 매니페스트에 성공으로 적는다.**
그래서 `assertRendered()` 가 있다 — 🔴 그 둘은 **HTTP 200 이라 상태코드로는 안 걸린다.**

## 검증

- 🟢 **대조군 — 기본 동작 불변**: `--dry-run` 의 여덟 주소가 **한 글자도 안 바뀐다**
- 🟢 **호스트 override**: `CAPTURE_CONSOLE_BASE=http://console.local` → 주소가 바뀌고 ⚠ 경고
- 🟢 **bite (주입 · 실행 · 물기를 각각)**: `NEEDS_AUTH=true` 로 바꾼 복사본에서
  ①주입 확인 ②`--dry-run` 은 자격증명 없이 **rc=0** ③진짜 실행은 **rc=1** + 사유 출력
- 🔴 **순서 결함을 하나 만들 뻔했다** — 자격증명 검사를 처음에 `--dry-run` **앞**에 뒀다.
  그러면 자격증명 없는 clean CI 에서 dry-run 이 rc=1 로 죽고 가드 `(z38)` 이 기대하는
  「설치 여부에 따른 rc 0/3」이 깨진다. 🔵 **이 파일은 같은 부류를 이미 한 번 겪었다**
  (`--dry-run` 이 의존 해석보다 먼저 반환 — `TASK-MONO-643`). 검사를 뒤로 옮겼다.
- 🔴 **장을 «추가» 하지 않았다.** `(z37)` 이 이 파일의 목록과 `index.html` 의 SHOTS 를
  대조하므로, 찍지도 않은 장을 목록에 넣으면 그 가드가 문다. **능력만 만들고 목록은

## 🔴 ① 의 결론은 **현재 600 에서도 이미 거짓이다**

실측 요금(AWS 공개 요금표, 발행 `2026-09-10`, `ap-northeast-2` · Linux · 온디맨드):

| 타입 | 시간당 | 메모리 |
|---|---|---|
| `m6i.2xlarge` (주석의 근거) | **$0.4720** | 32 GiB |
| **`r6i.2xlarge`** (배포된 것) | **$0.6080** | 64 GiB |

⇒ **28.8% 높다.**

```
주석 기준  600분 × $0.472 = $4.72  ≈ "$5"        ← 산술은 내부적으로 맞다
실제      600분 × $0.608 = $6.08                 ← 타입이 틀렸다
결론      $6.08 + EBS $9 = $15.08  >  "월 $15 미만"   ← 부등호가 이미 뒤집혀 있다
```

🔵 **주석의 산술을 탓할 것이 아니다** — 그때는 맞았다. 틀린 것은 **인스턴스가 바뀐 뒤에도 그 문장이 남아 있는 것**이다.

⚪ **EBS `$9` 는 이 티켓이 재지 못했다.** AWS 공개 EBS 엔드포인트가 404 라 저장소가 적어 둔 값을 그대로 인용했다. 🔴 그러므로 *"$15 를 넘는다"* 의 **정확한 판정은 EBS 실측에 달려 있다** — 컴퓨트 축($6.08 · $12.16)만이 측정값이다. AC-2 가 이것을 다룬다.

# 왜 1200 인가 (소유자 결정의 근거를 남긴다)

## 「600 단위」에 기계적 근거는 없다

예산 로직은 `handler.py:275` 의 **`return u["seconds"] >= BUDGET_MINUTES * 60` 한 줄이 전부**다.
구간·임계·경고 밴드·반올림이 **0건** ⇒ `1013` 도 `1200` 과 똑같이 유효하다.
**`600` 은 단위가 아니라 둥근 수였다.**

## 진짜 단위는 «창» 이고, 실측했다

CloudWatch `CPUUtilization` 데이터포인트로 지난 5일 가동 구간을 셌다
(인스턴스 `i-0863ba8d8faf52c63`, period 300s, 37 포인트):

```
창 4개 / 185분  →  창 평균 46.2분   (부팅 9분 16초가 그 안의 순수 오버헤드)
```

| 분 | 시간 | 창/월 | 컴퓨트/월 | +EBS(~9) |
|---|---|---|---|---|
| **600 (현재)** | 10.00 | 13.0 | $6.08 | $15.08 |
| 900 | 15.00 | 19.5 | $9.12 | $18.12 |
| 1000 | 16.67 | 21.6 | $10.13 | $19.13 |
| **1200 (결정)** | **20.00** | **25.9** | **$12.16** | **$21.16** |

## 결정 근거 셋

1. 🔴 **600 은 실측으로 부족하다** — 2026-09 에 **11일 만에 543분**(창 약 11.7개)을 썼고 **중간에 동났다**. 남은 19일에 57분뿐이라 창을 한 번도 넉넉히 못 연다.
2. 🔵 **1000 vs 1200 의 비용차는 $2.03/월** — 판단 근거가 되기엔 너무 작다. 그래서 비용이 아니라 **가독성**으로 갈랐다: 이 저장소는 이미 **시간으로** 쓴다(`variables.tf:148` = *"600분(10시간)"*). `1200` 은 *"1200분(20시간)"* 으로 그대로 들어가지만 `1000` 은 *"16시간 40분"* 이라 같은 문장에서 깨진다. ⇒ **정시로 떨어지는 값**이 그 자리에 맞다.
3. 🔴 **설정값 = 그달 최악 청구다.** `variables.tf:146-147` 이 직접 말한다 — *"idle_minutes / max_runtime_minutes 는 반복 호출로 리셋되므로 지출 상한이 아니다. **이 값만이 실질적 상한**"*. 1200 의 최악은 컴퓨트 **$12.16**(+EBS ≈ $21). 🔵 «크면 공짜로 좋다» 가 아니라 **그 최악값을 받아들인다는 결정**이다.

# Edge Cases

- **tfvars 에 `monthly_budget_minutes` 가 생겼다** → default 를 고쳐도 무효. AC-0 이 막는다.
- **plan 에 인스턴스 교체가 뜬다** → 🔴 STOP. 예산 변경이 아니라 **다른 일**이 섞인 것이다.
- **apply 는 성공했는데 `/status` 가 600 을 준다** → Lambda 가 옛 환경변수를 들고 있는
  것이다(콜드 스타트 전). 🔵 몇 초 뒤 다시 읽어 보고, 계속 600 이면 **apply 가 Lambda 를
  실제로 갱신했는지** 부터 본다. 🔴 *"적용됐겠지"* 로 닫지 마라.
- **EBS 를 재려다 못 쟀다** → ⚪ 로 남기고 **컴퓨트 축만** 단언한다. AC-2 ①.
- **요금이 그 사이 바뀌었다** → 이 티켓의 표를 상속하지 말고 **AC-0 에서 다시 읽은 값**을 쓴다.

# Failure Scenarios

- **F1 — 값만 바꾸고 주석을 둔다.** 🔴 그러면 **주석이 새 값을 더 크게 틀리게 설명한다**
  (600 에서 $1.36 틀리던 오차가 1200 에서 $2.72 가 된다). → AC-2 가 같은 커밋을 강제한다.
- **F2 — `.tf` 가 바뀐 것을 판정으로 쓴다.** 선언 ≠ 런타임. → AC-4 가 `/status` 를 읽는다.
- **F3 — plan 을 건너뛰고 apply 한다.** 🔴 이 스택에서 apply 는 **인스턴스를 교체할 수 있다.**
  → AC-3 이 plan 을 선행시키고 `destroy != 0` 이면 STOP.
- **F4 — 「월 $N 미만」을 못 잰 EBS 로 다시 쓴다.** 🔴 그것이 이 티켓이 고치려는 결함과
  **같은 종류**다(측정 안 한 값으로 부등호를 만드는 것). → AC-2 ① 이 ⚪ 를 강제한다.
- **F5 — 🔴 이미 일어났다. `m6i` 가 셋뿐이라고 믿었다.** 「셋」은 grep 의 결과이지 성질이
  아니었고, 그 grep 의 **모집단이 `infra/demo/aws/` 로 좁았다** ⇒ `infra/demo/README.md` 의
  ④⑤ 를 통째로 놓쳤다. 🔵 AC-2 의 마지막 칸이 구현 중에 잡았다.
  → 그래서 그 칸은 이제 **«루트에서 돌려라» 와 «0건이 아니라 남은 것과 이유를 적어라»** 를
  명시한다. 🔴 «전수» 라고 쓴 숫자를 볼 때마다 **어느 디렉터리에서 셌는지**를 물어라.
- **F6 — 예산이 올라간 것을 「리셋됐다」로 읽는다.** 쓴 543 분은 그대로 있고 **천장만**
  올라간다. → AC-4 의 ⚪ 칸이 그 구분을 적는다.

## AC-1 · AC-2 — 값과 근거를 같은 커밋에

- `monthly_budget_minutes` default **600 → 1200**.
- `description` 의 *"매월 1일 리셋"* 은 **참이라 유지**하되 **`UTC`** 를 명시했다 —
  `_usage()` 가 `_month()` = `time.strftime("%Y-%m", time.gmtime(...))` 로 판정하므로
  KST 자정이 아니라 **UTC 달력월**이다. 🔵 이 호스트가 KST 라 그 구분이 실제로 갈린다.

## 실측 — 지금 배포된 둘은 **다른 세대다**


🔴 **그러므로 배포된 `demo-up.sh` 는 「vercel 행은 안 찌른다」 + 「하한 2」 세대이고, 서빙 중인

티켓의 (b) 는 *"AMI 태그로 남기고 **nightly 가 그 태그와** `origin/main` 을 대조"* 다.

⇒ **두 겹으로 나눈다** — 축이 둘이라 판정도 둘이다:

| 축 | 무엇을 재나 | 어디서 |
|---|---|---|

**그 핀이 거짓말을 못 하게** 한다. 태그는 사람이 적는 값이 아니다 — packer 2단계가
`git rev-parse HEAD` 로 확증하고 통과한 값만 태그가 된다.

**왜 나머지가 아닌가:**

- **(a) 부팅 때 자기 세대와 론처 세대를 대조** — ✖ 두 이유로. ① 티켓이 적은 대로 그 코드가
  AMI 안에 있어 **첫 회를 못 잡는다**(정확히 잡아야 할 그 한 번을 놓친다). ② ①-b 가 드러낸
  더 큰 문제: 부팅 판정은 지금 **자기 세대만** 읽으므로 대조하려면 부팅이 **Vercel 을
  네트워크로 가져와야** 한다 ⇒ 부팅 완료 판정에 외부 의존을 하나 더 다는 것이고, 그것이
  실패하면 «데모가 안 떴다» 로 읽힌다 — 이 티켓이 없애려는 바로 그 증상이다.
- **(c) 계약 버전 번호** — ✖ 올리는 것을 잊으면 공허해지는 **게이트 없는 숫자**다(티켓이
  스스로 적었다). 게다가 맞춰야 할 것이 넷(마크업·소비자·오버레이·`projects.sh`)인데
  숫자 하나가 그 넷을 대표한다는 보장이 없다. 지금 방식은 **파일 자체를 비교**하므로
  올릴 것이 없다.
- **(d) 잴 수 없다고 명시 + 체크리스트** — ✖ 단독으로는 산문이고 산문에는 게이트가 없다.
  🔵 **버리지는 않았다** — AC-4 가 체크리스트를 쓰되 **그 뒤에 러너를 붙였다.**

## AC-2 — bite. 🔴 그리고 **주입을 읽기 전에 단언한다**

`--self-test` 가 네 칸을 돌린다. 주입 대상은 **위치가 아니라 성질로** 고른다:

| 칸 | 주입 | 기대 |
|---|---|---|
| ① | 같은 커밋을 양쪽에 | `0` 같은 세대 |
| ② | `demo-up.sh` 의 **blob 이 실제로 다른** 가장 최근 옛 커밋 | `1` 어긋남 |
| ③ | 존재하지 않는 커밋 | `2` 판정 불가 (**«못 쟀다» 가 «괜찮다» 로 안 접히는지**) |
| ④ | **오버레이 집합이 다른** 커밋(= 오버레이를 추가/삭제한 커밋의 부모) | `1` + **그 분기가 이름을 찍었는지** |

실행 결과 `0 / 1 / 2 / 1(분기적중=1)` — rc=0.

🔴🔴 **칸 ④ 는 장식이 아니다. 이 판정자의 실제 결함을 잡았다.**
초판의 `blob_at` 은 맨 `git rev-parse "<rev>:<path>"` 였는데, 그 명령은 경로가 그 커밋에
없을 때 **인자를 그대로 stdout 에 되뱉는다**(rc=128 인 채로):

```
$ git rev-parse afebc9371:infra/demo/console-vercel.override.yml 2>/dev/null
afebc9371:infra/demo/console-vercel.override.yml       ← 빈 문자열이 아니다
```

⇒ 「한쪽에만 있는 파일」 분기가 **한 번도 못 물었고**, 신설된 console 억제가
«내용 다름» 으로 오분류됐다. **rc 는 두 경우 모두 1 이라 rc 만 보면 구별이 안 된다.**
`--verify --quiet` 로 고쳤고, 칸 ④ 가 이제 **어느 분기가 물었는지**를 단언한다.
🔵 잡은 경로: 기대한 문구가 안 나오길래 두 커밋의 트리를 `git ls-tree` 로 직접 세어 봤다.

🔵 칸 ④ 의 후보를 «최근 N개 커밋» 에서 안 찾는다 — 그건 **예약된 자살**이다(main 이
N 개만 더 자라면 창 밖으로 밀려나 어느 날 갑자기 판정 불가가 된다). 대신 **오버레이를
추가/삭제한 커밋의 부모**를 쓴다. 그 사건은 과거이므로 개수가 줄지 않는다.

🔵 **재굽기가 이 bite 를 공허하게 만들지 않는다**(Edge Case ②): 주입은 «지금 어긋나 있다»
가 아니라 역사에서 온다.

## AC-3 — 러너. 🔴 자가검사와 실판정을 **다른 레인에** 둔 것은 결정이다

| 무엇 | 어디 | 왜 |
|---|---|---|
| `--self-test` | `ci.yml` → **Demo wrapper smoke** (paths-filter `infra/demo/**`) | 판정자가 **무는지**를 PR 마다. 싸고 결정적 |
| `bake.sh --dry-run` | 같은 잡 | 🔴 굽기 래퍼가 가질 수 있는 **유일한 러너**다. 템플릿이 `repo_commit`·`RepoCommit` 을 여전히 갖는지 확인 — 없으면 굽기 1시간 뒤 3단계에서야 안다 |
| **실판정** | `nightly-e2e.yml` → **`ami-generation-watch`** (신설 잡, `fetch-depth: 0`) | 시계가 필요하다: 재굽기는 **커밋 없이** 상태를 되돌린다 |

**`Demo wrapper smoke` 의 새 자가검사 스텝이 CI 에서만 `rc=2` 로 죽었다** — 로컬은 초록.
원인은 판정자가 아니라 **재는 곳의 모양**이었고, 두 겹이었다:

1. **얕은 PR 체크아웃에는 `origin/main` 이 없다.** `actions/checkout@v4` 는 기본으로 PR ref
   하나만 가져오므로 원격 추적 브랜치가 안 생긴다. 자가검사의 기본 기준이 그것이었다.
2. **`git log` 가 커밋 하나만 돌려준다**(fetch-depth=1) ⇒ 주입 후보를 못 찾아 «대조군
   성립 불가».

🔴🔴 **그리고 진짜 결함은 세 번째였다 — 같은 함정의 재발이고, 「고친 뒤에」 났다.**
`git rev-parse` 는 해석에 실패해도 **인자를 그대로 stdout 에 되뱉는다**(rc=128 인 채로).
그것을 § AC-2 에서 `blob_at` 하나에 대해 고쳐 놓고 **형제 호출들을 안 고쳤다**:

```
$ git rev-parse origin/main^{commit} 2>/dev/null    # 그 ref 가 없는 얕은 체크아웃에서
origin/main^{commit}                                 ← 빈 문자열이 아니다   rc=128
```

⇒ `REF_SHA` 가 그 리터럴을 받아 「비어 있지 않으니 해석된 것」으로 읽혔고, **HEAD 로
떨어지는 폴백이 영원히 안 도는** 채로 그 다음 줄에서 죽었다. 🔵 「고치기 전에 형제를
grep 하라」가 정확히 이 모양이다 — 한 자리만 고치면 형제가 낙오한다.

**고친 것** (판정 축은 안 바꿨다 — **재는 곳의 모양**만 받아들였다):

- 파일 안의 **모든** `rev-parse` 호출 → `--verify --quiet`. `bake.sh` 의 한 자리도 같이.
- 자가검사 기준이 `origin/main` 을 못 읽으면 **HEAD 로 떨어지고 그 사실을 찍는다.**
  🔴 실판정은 안 떨어진다 — 거기서 기준이 틀리면 답이 틀리므로 `2` 로 멈춘다.
  (자가검사에서 기준이 무엇인지는 재는 축이 아니다. 재는 것은 «칸을 가르는가» 다.)
- 얕은 체크아웃이면 주입 후보를 찾을 때까지 `fetch --deepen` 50 → 200 → 1000 재시도.
  🔵 워크플로에 `fetch-depth: 0` 을 박는 대신 여기서 판 이유: 그 잡은 다른 가드도 도는
  15분짜리이고, 전체 역사 클론을 그 전부에 물릴 이유가 없다.

**재현으로 확인했다** — 추측이 아니라 CI 의 모양을 로컬에 만들어 쟀다:

```
git clone --depth 1 --branch task/mono-628-ami-generation <repo> shallow
  → is-shallow=true · commits=1 · refs = PR 브랜치 하나 (origin/main 없음)
고치기 전: rc=2  «기준 ref 'origin/main' 를 못 읽습니다»
고친 뒤  : rc=0  «'origin/main' 를 못 읽어 HEAD 를 기준으로 씁니다» → 50 커밋 더 → 0/1/2/1
          bake.sh --dry-run  rc=0
```

🔵 **이 사건이 AC-3 의 근거를 강화한다**: 자가검사에 러너가 없었다면 이 세 겹은 nightly
첫 실행까지 안 보였을 것이고, 그때는 원인이 「판정자가 틀렸다」로 읽혔을 것이다.

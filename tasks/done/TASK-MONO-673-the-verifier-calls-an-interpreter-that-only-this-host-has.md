# 🔴🔴 요지 — 두 환경이 **정반대**이고, `command -v` 는 둘 다 「있다」고 답한다

| 환경 | `python` | `python3` |
|---|---|---|
| **packer AMI 빌드 호스트** (Ubuntu) | 🔴 **없다** | 🟢 있다 |
| **이 개발 호스트** (Windows) | 🟢 있다 (3.12.10) | 🔴 **Microsoft Store 스텁** |
| GitHub `ubuntu-latest` (CI) | 🟢 있다 | 🟢 있다 |

⇒ **어느 한쪽을 하드코딩하면 반대쪽이 깨진다.**

🔴🔴 그리고 **존재 확인으로는 못 고른다.** 이 Windows 호스트에서 실측:

```
command -v python3   →  "있다고 함"        (WindowsApps 의 Store 별칭 스텁)
python3 -c 'import sys'  →  🔴 안 돈다     ("Python was not found; run without arguments to install…")
python  -c 'import sys'  →  🟢 실제로 돈다
```

⇒ `command -v python3 || command -v python` 같은 관용구는 **이 호스트에서 고장난 스텁을
고른다.** 술어는 **실행**이어야 한다:

```sh
for c in python3 python py; do
  if "$c" -c 'import sys' >/dev/null 2>&1; then PY="$c"; break; fi
done
```

🔵 이건 이 저장소가 반복해서 적어 둔 그 규율이다 — **선언(존재)이 아니라 런타임(실행)을 재라.**

(**존재가 아니라 실행**)와 같은 말이다.

## 🔴 곁가지 — 내 standalone 재현이 공허했다

(z2) 를 손으로 떼어 재현했더니 **전/후 둘 다 초록**이었다. 원인: LIVE 게이트를
`grep 'if [ "$LIVE" -eq 0 ]' | head -1` 로 잡아 **99행**이 나왔고, 요구 추출이 **0건**이

스크립트는 공용 `live_gate_line`(정확히 일치하는 한 줄, 0개면 실패·2개 이상이면 판정 불가)을
쓴다. ⇒ **내 재현은 술어를 복제하지 못했고, 0건을 «요구 없음» 으로 읽었다.**

🔵 그래서 재현을 버리고 **가드가 실제로 쓰는 한 줄**을 직접 걸었다:

|---|---|

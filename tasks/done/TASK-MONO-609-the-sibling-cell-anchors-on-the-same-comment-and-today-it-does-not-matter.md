# Acceptance Criteria

## AC-0 — verify-then-act

착수 시점에 **두 경계가 여전히 다른지**, 그리고 **두 도구 집합이 여전히 같은지** 다시 재라.

- 경계가 같아졌으면 누가 고쳤는지부터 찾고 **STOP**.
- 🔴 **집합이 이미 달라졌으면** 그건 잠복이 끝났다는 뜻이다 — 우선순위가 올라간다.
  그때는 `(z2)` 가 **지금 무엇을 놓치고 있는지**부터 적어라.

## AC-1 — 주입으로 물기를 증명한다

- 🔴 **주입을 먼저 단언하라** — 경계 사이(2699~2914)에 `command -v <없는도구>` 를 넣고,
  그 줄이 **진짜 게이트 «앞»이고 옛 경계 «뒤»** 인지 줄 번호로 확인한다.
- 고치기 **전** 판본: 그 도구가 `z2_seen` 에 **안 나타난다**(= 놓친다).
- 고친 **후** 판본: 나타나고, packer 에 없으므로 **FAIL** 한다.
- 🔵 **두 방향 다** — 옛 경계 «앞»에 넣은 도구는 양쪽 다 잡아야 한다(음성 대조군).

## AC-2 — 0건 하한은 이미 있다. **약해지지 않았는지** 확인만 한다

`(z2)` 에는 이미 *"추출 0건을 '의존 없음' 으로 보고하지 않습니다"* 하한이 있다.
🔴 앵커를 고치면서 그것이 **여전히 도달 가능한지** 확인하라 —
경계가 파일 뒤로 밀리면 0건이 나올 확률은 오히려 줄지만, **하한을 지웠는지**는 별개 문제다.

## AC-3 — 🔴 **복제하지 마라**

`(z16)` 과 `(z2)` 가 이제 같은 앵커를 쓴다. **같은 사실이 두 곳에 생기면 한쪽만 고쳐진다.**
공용 헬퍼(예: `live_gate_line <file>`)로 뽑을지, 아니면 두 곳에 두되 **서로를 이름으로 지목하는
주석**을 달지 결정하고, 그 결정을 적어라. [[feedback_one_fact_in_two_sections_only_one_gets_fixed]]

## AC-4 — 안 고치는 것을 적는다

- `(z2)` 가 `if [ -f "$z2_pkr" ] && [ -f "$z2_self" ]; then` 안에 통째로 들어 있고
  **else 가 없다** — 파일이 옮겨지면 이 칸은 **조용히 사라진다**. 그 축은 이 티켓이 안 본다.

# ✅ 구현 (2026-09-01)

## ✅ AC-0 — verify-then-act: **잠복은 그대로였다**

| 축 | 값 | 판정 |
|---|---|---|
| `(z2)` 가 쓰던 경계 | **2699** (= `(z16)` 의 서술 주석) | 여전히 다르다 |
| 진짜 게이트 | **2914** | 차이 **215줄** |
| 두 경계의 `command -v` 집합 | 둘 다 `[node]` | **여전히 같다** ⇒ 잠복 지속 |

⇒ STOP 조건(누가 이미 고쳤다 / 집합이 이미 갈렸다)에 **해당하지 않는다.**

## AC-3 를 **먼저** 정했다 — 구현이 그 결정에 달려 있기 때문이다

> **결정: 앵커를 «한 상수」로 뽑는다.** 서로를 지목하는 주석이 아니라 **공용 정의**다.

세어 보고 정했다. 608 이 끝난 시점에 앵커 리터럴은 **코드에 5곳**이었다:

| 곳 | 무엇 |
|---|---|
| `(z2)` × 1 | 느슨한 앵커(이 티켓의 결함) |
| `(z16)` × 4 | 개수 세기 · 줄 번호 · **bite 주입 awk** · 주입 위치 단언 |

🔴 주석만 달았다면 **다섯 곳이 그대로 남는다.** 그리고 그중 하나(awk)는 문법이 달라
«한쪽만 고쳐지는» 확률이 가장 높은 자리다.

🔵 **정규식이 아니라 고정 문자열로 뽑았다** — `LIVE_GATE_LINE='if [ "$LIVE" -eq 0 ]; then'`.
`grep -x -F` 와 awk 의 `$0 == gate` 가 **같은 뜻으로** 읽는다. 정규식 상수였다면 awk 의
**동적 정규식 이스케이프**(`\[`·`\$` 를 awk 가 어떻게 읽는지)에 의존했을 것이고, 그건
«두 곳에 적는 것» 을 «두 문법으로 적는 것» 으로 바꿨을 뿐이다.

공용 헬퍼 `live_gate_line <file>` 은 **줄 번호를 stdout 으로, «몇 개였나» 를 종료코드로**
돌려준다(0=하나 · 1=없음 · 2=둘 이상). 🔴 **판정 문구는 부르는 쪽이 정한다** — 칸마다 그
사실이 뜻하는 결함이 다르기 때문이다. 다만 **결론(«둘 이상 = 판정 불가»)은 같아야** 한다.

**결과: 코드상의 앵커 리터럴 5곳 → 1곳**(`LIVE_GATE_LINE` 정의). 나머지 등장은 주석과
게이트 자신뿐이다.

## ✅ AC-1 — 주입으로 물기를 증명했다 (2×2)

🔴 **주입을 먼저 단언했다** — 줄 번호로, 그리고 그 줄이 두 경계의 **어느 쪽**인지로.

대상은 **손 안 댄 옛 파일**(경계 2699 / 게이트 2914)이고, 술어만 갈아 끼웠다:

| 주입 위치 | 옛 술어 | 새 술어 |
|---|---|---|
| **A — 두 경계 «사이» (2806)** | 🔴 **rc=0, 놓친다**(`요구: node` — zzztool 이 없다) | ✅ **rc=1, 문다**(`… 설치하지 않습니다: zzztool`) |
| **B — 옛 경계 «앞» (2694)** | rc=1, 문다 | rc=1, 문다 |

🔵 **B 가 음성 대조군이다.** 옛 술어가 *«늘 눈이 멀었다»* 가 아니라 **그 215줄 창에서만**
멀었다는 것을 이 행이 고정한다. B 가 없었으면 «옛 술어는 아무것도 안 본다» 로 과대주장했을 것이다.

🔵 하네스는 술어를 **재구현하지 않는다** — 대상 파일에서 `(z2)` 블록(+ 상수·헬퍼)을 **그대로
잘라** 돌리고 `z2_self`/`z2_pkr` 만 치환한다.

## ✅ AC-2 — 0건 하한은 살아 있고, **약해지지 않았다**

게이트 앞의 `command -v` 를 **2건 → 0건**으로 지운 픽스처에서:

```
rc=1
FAIL: (z2) 정적 구간에서 'command -v' 선언을 하나도 추출하지 못했습니다
```

🔵 경계가 뒤로 밀렸으므로 0건이 나올 확률은 **줄었지만**, 하한이 **도달 가능한지**는 별개
질문이고 그것을 따로 쟀다.

## ✅ Edge Case — 게이트가 둘일 때 **두 칸의 판정이 갈리지 않는다**

게이트를 하나 더 심은 픽스처(총 2개)에서:

| 칸 | 결과 |
|---|---|
| `(z2)` | `rc=1` — *"LIVE 게이트가 2개입니다 — 어느 것이 정적 구간의 끝인지 판정할 수 없습니다"* |
| `(z16)` | `rc=1` — *"열 0 의 LIVE 게이트가 2개입니다 — 어느 것이 그 게이트인지 판정할 수 없습니다"* |

문구는 다르고 **결론은 같다.** 티켓의 Edge Cases 가 요구한 그대로다.

## 🔵 `(z16)` 회귀 — 608 의 행렬을 그대로 다시 돌렸다

| 입력 | 결과 |
|---|---|
| 손 안 댄 파일 | `rc=0` ok |
| 게이트 **안**에 칸 주입 | `rc=1` — `zzz1` 지목 |
| 게이트 **위**에 칸 주입 | `rc=0` ok |

608 이 남긴 것과 **동일**하다. 이 리팩터가 형제를 안 깨뜨렸다.

🔴 **그 과정에서 하네스 결함을 하나 잡았다.** 첫 실행이 3/3 빨강이었는데 원인은 회귀가 아니라

하네스에 상수·헬퍼 추출을 넣어 갈랐다. 실패를 그대로 «회귀» 로 보고했으면 이 PR 을 되돌렸을 것이다.

## 🔵 부수 — AC-4 의 위험을 하네스가 **실연**했다

`(z2)` 는 통째로 `if [ -f "$z2_pkr" ] && [ -f "$z2_self" ]; then` 안이고 **`else` 가 없다.**
하네스 초안이 packer 경로를 틀리게 잡자 칸이 **rc=0 으로 조용히 사라졌고, 그것이 통과처럼 보였다.**
⇒ 하네스에 *"packer 경로는 필수 인자, 없으면 즉시 실패"* 를 넣었다. 🔴 **그러나 진짜 파일의
그 축은 이 티켓이 안 고친다**(AC-4 아래).

## ✅ AC-4 — 이 수리가 **안 고치는 것**

# 🔴 왜 — 실제로 밟았다 (`TASK-MONO-659`, 2026-09-11)

`outbound-service` 에 `V10__order_schema_align.sql` 이 이미 있는데 같은 번호로
`V10__denormalise_sku_code_on_order_line.sql` 을 넣었다. CI 가 이렇게 죽었다:

```
Caused by: org.flywaydb.core.api.FlywayException at CompositeMigrationResolver.java:92
```

## 🔴🔴 그 신호가 **「번호가 겹쳤다」로 안 보인다**

보이는 것은 이 화면이다:

```
EventDedupePersistenceIntegrationTest > … FAILED
FulfillmentRequestedConsumerIT > … FAILED
SagaSweeperIT > … FAILED          (외 12건)
```

**통합 테스트 15개가 무더기로 FAILED** 이고 그중 **어느 것도 마이그레이션을 말하지 않는다** —
전부 «컨텍스트 기동 실패» 의 파생이다. 원인 줄은 스택 한가운데에 한 줄 있다.

## 🔴 그리고 **로컬에서는 볼 방법이 없었다**

이 저장소의 Testcontainers IT 는 로컬에서 못 돈다(알려진 블로커). ⇒ 푸시하기 전에는 알 수
없었고, **CI 왕복 한 번**이 들었다.

## 🔴 술어가 **알파벳 정렬**이었다 — 이것이 진짜 원인이다

659 는 `ls <dir> | tail -8` 로 「마지막 버전」을 봤다. `ls` 는 알파벳 순이라 `V10` 이 `V2` 보다
**앞**에 오고, `tail -8` 이 그 구간을 잘라냈다. **보인 최대값 `V9`, 실제 `V18`.**

⇒ 🔵 「V10 은 없다」가 아니라 **「내가 쓴 목록에 V10 이 안 보였다」** 였다 — 이 저장소가
이름 붙인 «부재를 주장하기 전에 술어를 의심해라» 그대로다.

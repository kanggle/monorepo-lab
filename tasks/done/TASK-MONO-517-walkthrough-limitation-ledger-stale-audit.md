장부다. 데모 상태를 묻는 대화 중 한 행이 눈에 걸렸다:

```
| 🔴 ERP 결재 상신이 항상 실패한다 — 결재는 DRAFT 로만 쌓인다 | … | TASK-ERP-BE-041 |
```

그런데 `TASK-ERP-BE-041` 은 **고쳐져서 닫혀 있었다**(impl `6583ae2d8` / close `6308b4097`).

🔴 **한 건으로 끝내지 않고 모집단을 다시 셌다.** 표에서 티켓을 인용하는 행 전부에 대해
*"그 티켓이 지금 어느 큐에 있나"* 를 기계적으로 물었다 — **26행 중 7행이 stale**.

## 🔴 왜 눈으로 훑을 때 안 보였나 — stale 5건이 **상태 이모지가 없던 옛 행**이었다

표는 나중에 `🔴/🟡/✅/🔵` 접두어 규약이 생겼는데 **초기 행들에는 적용되지 않았다.**
그래서 "🔴 를 훑는다" 는 탐지식은 stale 7건 중 **5건을 구조적으로 못 본다**.
전수를 티켓 큐로 물어야만 나온다.

# Edge Cases

- **`done/` 인데 한계는 남는 경우** — closed-as-decided. impl 커밋 확인으로 갈랐다
  (이번 7건은 전부 실제 수정 커밋이 있었다)
- **`done/` 인데 🟡 가 맞는 경우** — `TASK-PC-FE-273` 은 *"조사 종결(결함 아님)"* 로 닫혔고
  그 행의 🟡 는 정확하다. ⇒ 단순 "done 이면 ✅" 규칙은 **오탐**을 낸다(MONO-518 가드 설계 입력)
- **✅ 행이 done 티켓을 인용하는 것은 정상** — 고친 티켓을 가리키기 때문

# Failure Scenarios

- 🔴 **한 행만 고치고 끝낸다** → 나머지 6행이 그대로 남아 다음 면접에서 같은 오정보를 낸다.
  발견 하나를 모집단으로 착각하는 실패
- 🔴 **해소된 행을 삭제한다** → 표는 깨끗해지지만 "그게 왜 고쳐졌는지" 가 사라지고, 다음
  사람이 같은 결함을 다시 발견해 다시 조사한다
- 🔴 **규약을 적고 적용하지 않는다** → 다음 감사 때 같은 탐지 실패가 재현된다

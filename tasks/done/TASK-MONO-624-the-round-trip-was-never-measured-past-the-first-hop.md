## V1 (console) ✅ — 302 목적지가 IdP 다

```
GET https://console.hubwang.com/api/auth/login   →  307
Location: https://auth.hubwang.com/oauth2/authorize
  ?response_type=code
  &client_id=platform-console-web
  &redirect_uri=https%3A%2F%2Fconsole.hubwang.com%2Fapi%2Fauth%2Fcallback
  &scope=openid+profile+email+tenant.read
  &code_challenge_method=S256 &code_challenge=… &state=…
```

네 가지가 한 번에 확인됐다:

| 축 | 결과 |
|---|---|
| issuer 가 `C2` 의 고정 발급자인가 | ✅ `auth.hubwang.com` |
| `redirect_uri` 가 IdP 시드값과 일치하나 | ✅ `V0034`(`TASK-BE-589`)가 등록한 문자열과 **정확히** 일치 |
| Vercel 프로젝트에 OIDC env 가 주입됐나 | ✅ 안 됐으면 이 URL 이 조립될 수 없다 |
| PKCE | ✅ `S256` + `state` |

🔵 대조군: `/api/auth/__nope__` = **404** ⇒ 위 `307` 은 「모든 경로가 307」이 아니다.

## 🔴 그리고 `TASK-MONO-358` 축이 구조적으로 해소됐다

콘솔 로그인이 역사적으로 죽던 자리다(*"지금껏 동작한 콘솔 로그인은 `localhost:3000` 뿐"* —
평문 오리진에 `Secure` 쿠키를 주면 브라우저가 **저장조차 안 해서** 콜백이 `invalid_state`).

```
Set-Cookie: console_pkce_verifier=…; Path=/; Max-Age=600; Secure; HttpOnly; SameSite=lax
Set-Cookie: console_oauth_state=…;   Path=/; Max-Age=600; Secure; HttpOnly; SameSite=lax
→ cookie jar 에 둘 다 실제로 저장됨
```

🔴 **여기서 내 술어가 한 번 틀렸다** — 첫 파싱이 jar 를 «비어 있음» 으로 읽었다. curl 이
HttpOnly 쿠키를 `#HttpOnly_` **접두로** 쓰는데 `grep -v '^#'` 로 그 줄들을 지웠기 때문이다.
**없는 결함을 보고하기 직전이었다.** 재측정 시 같은 함정을 피하라.

      ⇒ V7 은 **창을 열기 전에** 재고, 나머지는 창 안에서 재라. **순서가 있다.**

- [x] **AC-1 — V2 (홉 ③)** ✅ 콜백의 `state` 가 쿠키 보관값과 **바이트 동일**. `invalid_state` 없음 콜백에서 `state`/PKCE 쿠키가 살아 돌아오는가.
      통과 기준 = 콜백이 `invalid_state` 를 **안 낸다**.
      🔴 판정은 **최종 화면이 아니라 콜백 응답**으로 한다 — 로그인 후 화면이 떠도 그 경로가
      쿠키를 썼다는 증거는 아니다.

- [x] **AC-2 — V3 (홉 ⑤)** ✅ 쿠키 5종 전부 `Secure; HttpOnly; SameSite=lax` — **응답 헤더를 찍었다**(추론 아님). 일회용 2종은 `Expires=1970` 소거 세션 쿠키의 `Secure`/`SameSite` **실제 값**.
      🔴 **추론이 아니라 응답 헤더를 찍는다.** 위 § 의 `console_pkce_verifier` 처럼 원문을 적어라.

- [x] **AC-3 — V4 로그아웃** ✅ `POST /api/auth/logout` 200 · 쿠키 6종 소거 · 이후 보호 화면이 무세션 대조군과 **같은 모양**. ⚪ IdP 쪽 `JSESSIONID` 종료는 **미측정**(별도 축) (`/connect/logout`).
      🔴 **로그인만 재고 «왕복 OK» 라고 적지 마라** (`TASK-MONO-574` AC-2 가 그 실패를 기록했다).

- [x] **AC-4 — V5 부팅 2회 연속** ✅ **본체 통과** — IP 가 `3.38.133.85`→`43.203.143.165` 로 바뀐 부팅 #2 에서 **저장소·Vercel env 를 아무것도 안 고치고** 로그인 성립 로그인, 사람 개입 없이.
      🔴🔴 **이것이 `ADR-MONO-069` 의 본체다.** 축 ②(범위)는 «한 번 됐다» 로 판정되지 않는다 —

      🔵 두 번째 부팅이 **다른 창**이어도 된다. 그때 «첫 창에서 손댄 것이 없다» 를 함께 적어라.

      🔴 호스트에서 잰 200 은 이 축의 답이 아니다 — 헤어핀은 내부→외부→내부 경로다.

# Edge Cases

① **데모를 켠 창이 이 티켓 전용이 아닐 수 있다.** 그러면 다른 작업과 창을 나눠 쓴다 —
   🔴 그때 **먼저 V2~V4 를 잡아라**(짧다). V5 는 창 두 개가 필요하므로 마지막이다.

② 🔴 **반쯤 잰 V5 는 안 잰 V5 보다 나쁘다.** «첫 부팅은 됐다» 를 V5 통과로 적으면 그것이
   정확히 이 ADR 이 금지한 «단일 표본의 성질 승격» 이다. 못 재면 **⚪ 로 남기고 왜인지 적어라.**

③ **`auth.hubwang.com` 이 200 이라고 IdP 가 준비된 것은 아니다.** `C2` 는 Vercel 포워더가
   앞에 있으므로, 포워더가 살아 있고 뒤가 안 떴을 때의 응답을 구별해야 한다.
   🔵 판정은 `/.well-known/openid-configuration` 의 **본문**으로 — 200 만 보지 마라
   ([[env_gateway_401_is_not_backend_readiness]] 와 같은 부류).

④ **쿠키를 curl 로 잴 때 `#HttpOnly_` 접두를 지우지 마라** — 위 § 에서 실제로 밟았다.

⑤ **로그인에는 자격증명이 필요하다.** 시드된 운영자 계정을 쓰고, **어느 계정으로 쟀는지**
   적어라. 계정마다 테넌트/권한이 달라 «로그인은 됐는데 화면이 비었다» 가 나온다.

# Failure Scenarios

① **V2 가 `invalid_state` 로 실패** → 🔴 이 티켓은 **고치지 않는다.** 쿠키 원문 + 콜백 응답을
   그대로 적고 **별도 티켓**으로 올린다. `TASK-MONO-358` 이 같은 증상의 다른 원인을 갖고 있으니
   그 티켓을 먼저 읽어라(평문 오리진 축은 이제 해당 없음 — HTTPS 다).

② **V5 의 두 번째 부팅에서 사람 손이 필요했다** → 그것이 **발견**이다. 무엇을 손댔는지
   적고 `ADR-MONO-069` 의 *"부팅마다 사람이 하는 일: 없다"* 주장과 대조하라 — ADR 의 표가
   틀렸다는 뜻이 된다.

③ **창이 닫혀 못 끝냈다** → ⚪ 로 남기고 **어느 V 가 안 쟀는지 칸 단위로** 적는다.
   🔴 «대부분 통과» 같은 요약으로 덮지 마라.

(첫 랜딩 2026-09-01T11:05Z) **이후**에 구워졌으므로 콘솔 콜백이 IdP 에 들어 있다.
🔴 안 쟀으면 «콜백 미등록» 이라는 **AMI 낡음의 인공물**을 결함으로 보고했을 것이다.
🔴 반대로 이 AMI 는 `618`(fan 억제)·`625` **이전**이다 — 이 창의 데모는 팬을 아직 띄운다.
그 드리프트는 이 티켓의 축이 아니지만, **이 창에서 본 것을 그대로 «지금 데모» 로 읽지 마라.**

## 결과 — **V1~V5·V7 통과, V6 부분**

전체 표는 `ADR-MONO-069` § Verification § ✅ 실측 결과 에 있다(AC-7 = 그 표의 **새 집**).
요약:

| # | 결과 | 한 줄 |
|---|---|---|
| V1 | ✅ | 307 → `auth.hubwang.com/oauth2/authorize`, `redirect_uri` 가 `V0034` 시드와 정확히 일치, PKCE `S256`. 음성 대조군 404 |
| V2 | ✅ | 콜백의 `state` 가 쿠키 보관값과 **바이트 동일** ⇒ 스킴 경계를 건너 살아 돌아왔다 |
| V3 | ✅ | 세션 쿠키 5종 전부 `Secure; HttpOnly; SameSite=lax` · 일회용 2종은 `Expires=1970` 소거 |
| V4 | ✅ | `POST /api/auth/logout` 200, 쿠키 6종 소거, 이후 보호 화면이 무세션 대조군과 **같은 모양** |
| V5 | ✅ | **IP 가 바뀐 부팅 #2 에서 아무것도 안 고치고 로그인 성립** |
| V6 | 🟠 **1/12** | 내부 리소스 서버가 우리 토큰의 클레임으로 인가 판정을 냈다(아래) |
| V7 | ✅ | 데모 `stopped` 에서 `/`→307→`/login` 200. **502 아님** |

**세션까지 성립함의 판정 방식** — 보호 화면이 **세션 有 `200` / 無 `307 → /login`** 으로
**갈리는 것**을 판정으로 삼았다. 🔴 «200 이 나왔다» 는 판정이 아니다 — 팬 표면에서
세션 有/無 가 **둘 다 200** 이라 로그인 페이지를 통과로 오독한 전례가 있다.

## 🔴🔴 첫 측정이 «없는 결함» 을 만들 뻔했다 — 기록한다

`Accept: */*`(curl 기본)로 `/oauth2/authorize` 를 찌르면 **401 + 빈 본문**이 온다.
그대로 적었으면 *"홉 ② 가 막혔다"* 가 됐을 것이다. **`Accept: text/html` 이면 302 → `/login`** 이다.

⇒ **그 401 은 IdP 의 결함이 아니라 내 클라이언트가 만든 것**이다. 브라우저 플로를 브라우저가
아닌 클라이언트로 재면 **실물보다 가난한 요청**이 되고, 그 차이가 결함처럼 보인다.
🔵 판별은 한 줄이었다 — **헤더 하나만 바꾼 A/B**.

## 🔴 V6 을 «12개» 로 못 쟀다 — 그리고 **왜 못 쟀는지가 처방을 정한다**

데모 내부 소비자를 직접 찌르려면 평문 HTTP(`*.sslip.io`)로 가야 하는데, **이 측정 호스트에서는
캡티브 포털이 평문 요청을 전부 먹는다.** 음성 대조군이 그것을 증명했다:

```
http://iam.<ip>.sslip.io/               404
http://console.<ip>.sslip.io/           404
http://web.fan-platform.<ip>.sslip.io/  404
http://nosuchhost-negctl.<ip>.sslip.io/ 404   ← 음성 대조군도 404 ⇒ 전부 먹힌 것
```

🔴 **음성 대조군이 없었으면 «데모 내부가 전부 죽었다» 로 오독**했을 것이다.

⇒ 대신 **HTTPS 경로로 간접 증거**를 얻었다. `/api/audit` 이 세션과 함께:

```json
{"code":"TENANT_SCOPE_DENIED","message":"Operator tenantId=demo-corp cannot query tenantId=iam"}
```

그 문구는 **우리 토큰의 클레임을 파싱한 데모 내부 리소스 서버만** 만들 수 있다
(무세션 = **401**, 세션 = **403** ⇒ 인증 뒤의 인가 판정). ⇒ **적어도 한 소비자는 새 issuer 를 검증한다.**

🔴 **그러나 1 은 12 가 아니다.** 나머지 11 은 **미측정**이고, «한 표면이 통과했으니 나머지도»
는 이 저장소가 이름 붙인 비약이다. 재려면 **인스턴스 안에서**(SSM 등) 각 소비자의 discovery +
JWKS 를 찔러야 한다 — 이 창에서는 그 경로가 없었다.

## ⚠️ 이 창에서 **못 한 것**

| 축 | 상태 |
|---|---|
| V6 의 나머지 11 소비자 | ⚪ **미측정** — 캡티브 포털. 인스턴스 내부에서 재야 한다 |
| IdP 세션(`JSESSIONID`) 의 RP-initiated logout | ⚪ **미측정** — 콘솔 쿠키는 전부 소거됐으나 IdP 쪽 세션 종료는 별도 축(`/connect/logout` 은 `id_token_hint` 없이 401) |
| `TENANT_SCOPE_DENIED` 의 `demo-corp` vs `iam` | ⚪ **판정 안 함** — 시드 불일치로 보이나 이 티켓의 축이 아니다 |

🔵 **셋 다 «결함» 으로 단정하지 않았다.** 미측정은 미측정이다.

## 🔵 별도 티켓이 필요한가 — **판정: 지금은 아니다**

이 티켓의 DoD 는 *"결함이 나왔다면 **별도 티켓**으로 기안됐다"* 이다.
**측정된 축에서 결함은 0건이다** — V1~V5·V7 이 전부 통과했고, 401 은 내 클라이언트가
만든 것이었다. 남은 것은 **결함이 아니라 미측정**(위 ⚠️ 3건)이고, 그중

- **V6 나머지 11** 은 이 ADR 의 축이므로 **`ADR-MONO-069` § Verification 에 ⚪ 로 남겼다** —
  그 표가 그 축의 집이고, 다음 창에서 인스턴스 내부 경로가 생기면 거기서 채운다.
- 나머지 둘은 이 ADR 의 축이 아니다.

🔴 **미측정을 티켓으로 만들면 «잴 수 없는 것» 이 큐에 영구히 앉는다** — 캡티브 포털은
이 호스트의 상태이지 저장소의 결함이 아니다. 그래서 티켓이 아니라 **표의 ⚪ 로** 남긴다.

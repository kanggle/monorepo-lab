# 🟢 AC-1 ⓑ · AC-2 · AC-3 — 구현 (2026-09-22 UTC · 분석=Opus 5)

## 🔴 먼저: ⓑ 를 «자동 기본값» 으로 만들지 **않았다**, 그리고 그 이유

ⓑ 의 문구는 *"콘솔의 ecommerce 화면이 `ecommerce` 테넌트를 **기본으로** 본다"* 였다. 그대로
하려면 둘 중 하나여야 하는데 **둘 다 내 권한 밖이다**:

| 길 | 왜 안 했나 |
|---|---|
| 섹션 진입 시 **자동 전환** | 활성 테넌트는 전역 상태다. `/ecommerce` 에 들어갔다고 바꾸면 **나올 때 잘못된 테넌트로 남는다**. 게다가 전환은 토큰을 민팅하는 **쓰기**라 GET 항해가 그것을 하면 안 된다 |
| ecommerce 클라이언트가 **자기 테넌트 토큰**을 민팅 | `session.ts` 가 assume 토큰을 *"Scoped to the current active tenant **BY CONSTRUCTION** (never served for a tenant ≠ the active-tenant cookie — both are set/cleared together)"* 로 못박았다. 그 결합을 끊는 것은 **ADR 결정**이다(HARDSTOP-09) |
| 기본 선택 규칙에 «섹션별 기본» 추가 | `active-tenant-default.ts` 의 ①②③ 은 **2026-09-16 소유자 결정**(`TASK-PC-FE-292`)이다. 내가 뒤집을 것이 아니다 |

🔵 **그래서 콘솔이 이미 가진 관용구를 넓혔다.** `TASK-PC-FE-292` 는 «테넌트가 없으면 빈
화면 대신 «테넌트를 먼저 선택하세요» 를 보인다»(`DomainTenantGate`)를 이미 만들어 뒀다.
빠져 있던 것은 **«선택은 됐는데 이 섹션에 안 맞는 테넌트»** 한 칸뿐이다.

## 구현 — `DomainTenantGate` 에 `productKey` (opt-in)

- 게이트가 이제 둘을 묻는다: ① 테넌트가 assume 됐나(기존) ② **그 테넌트가 이 섹션의
  product 가 서비스하는 테넌트인가**(신규, `productKey` 를 준 섹션만).
- 🔵 **관계로 판정하고 슬러그 목록으로 판정하지 않는다** — 레지스트리의
  `product.tenants` 와 활성 테넌트를 비교한다. `active-tenant-default.ts` 가
  `selectableTenants()` 에 대해 적어 둔 규율 그대로다(*"a list would break silently on the
  next rename"*).
- 🔴 **모든 불확실은 섹션 쪽으로 흐른다**: 레지스트리 저하 · product 부재 · `tenants` 빈
  배열 · 조회 예외 → **전부 섹션을 그대로 렌더한다.** 「확인 못 했다」로 막으면 레지스트리
  깜빡임이 섹션을 죽인다. **양성 답**(product 있음 + 테넌트 목록 있음 + 활성이 그 안에 없음)
  일 때만 안내가 뜬다.
- 🔴 **순서**: assume 이 아예 없으면 **기존 292 게이트가 이긴다** — 아무 테넌트도 안 고른
  운영자에게 «다른 테넌트로 전환하세요» 라고 말하면 안 된다.
- 🔵 `productKey` 는 **ecommerce 레이아웃 한 곳에만** 넘긴다. § 제외가 그렇게 요구한다 —

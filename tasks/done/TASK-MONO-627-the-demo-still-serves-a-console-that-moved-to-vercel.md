`TASK-MONO-625` 가 이 축을 이미 좁혀 뒀다(그 티켓 § AC-0 선실측 ③, **상속하지 말고 다시 확인**):

🔴 **AC-0 이 고르고, 고르지 않은 쪽을 왜 안 골랐는지 적는다.** 🔵 추천은 **A** 이지만

⇒ **필요한 것은 설계 결정**: 부팅 완료를 무엇으로 잴 것인가. 후보(전부 착수 전 추정):

| | 안 | 🔴 대가 |
|---|---|---|
| a | **Vercel 표면을 찌른다**(`console.hubwang.com`) | 🔴🔴 **부팅 판정이 아니다** — 데모가 꺼져 있어도 200 이므로 «부팅이 끝났다» 의 증거가 못 된다. **이 축을 죽이는 것과 같다** |
| b | 데모 호스트의 **비-방문자 표면**(게이트웨이·관측 도구)으로 축을 옮긴다 | 🔵 데모 호스트에 묶여 있고 실재한다. 🔴 «방문자가 여는 것» 이 아니므로 552 의 발견(컨테이너 99/102 healthy 인데 **표면** 전멸)과 축이 미묘하게 다르다 — 그 차이를 적어야 한다 |
| c | **축을 폐기**하고 그 사실을 명시한다 | 🔴 「컨테이너는 healthy 인데 화면은 502」를 잡는 유일한 축이 사라진다. 🔵 단, **명시적 폐기**는 조용한 공허와 다르다 |

🔴 **어느 것을 고르든 «하한만 0 으로 두고 넘어가는 것» 은 금지다.** 그것은 통과가 아니라
**계측기 상실**이다.

### (i) `router_hosts()` 가 **메시지 없이 죽는다**

```
for p in "${!COMPOSE[@]}"; do render "$p" | grep -oE 'Host\(...\)' | sed ...; done | sort -u
```

억제로 console 프로젝트의 렌더에 `Host(` 가 **0건**이 됐다(남은 `console-bff` 는
`TASK-MONO-362` 가 라우터를 일부러 없앴다). 그러자:

```
grep 0건 → rc=1 → pipefail → for 루프 서브셸이 set -e 로 즉사
→ router_hosts rc=1 → `router_hosts > "$hosts_file"` 실패 → 스크립트 즉사
```

🔴 **그 죽음에 아무 메시지가 없다.** 로그 마지막 줄이 `[verify] (i) …` 이고 rc=1 이라
**「가드가 물었다」와 모양이 완전히 같다.** 이 저장소가 이름 붙인 두 함정이 겹친 자리다 —
«0건 ≠ 없음» + «줄어드는 모집단에 하한을 걸면 성공이 고장난다».

고친 방법: ⓐ grep 0건을 `|| true` 로 정상으로 받고, ⓑ **조용히 넘기지 않는다** —
라우터 0개 프로젝트를 **이름으로 찍는다**. 🔵 겸사겸사 렌더를 캐시해 8개 프로젝트를
16번이 아니라 8번 렌더한다.

### (m) `render console` 에 `CONSOLE_PUBLIC_ORIGIN` 이 없어졌다

그 칸은 «오리진이 빠졌다» 로 빨개졌는데, 실제로는 빠진 것이 아니라 **그 서비스가 데모에
없는** 것이다. 🔴 하한을 없애는 것(«없으면 통과»)은 답이 아니다 — console-web 이 데모로
돌아온 날 오리진 누락이 **조용히** 통과한다. ⇒ **술어가 읽는 렌더를 base compose 로
옮기고**(이 스크립트는 `demo.env` 를 export 하므로 base 만 렌더해도 데모 값이 그대로
치환된다) **비공허성을 명시적으로 단언**했다(base 에서도 console-web 이 사라지면 빨강).

## 🔴 이 결함의 진짜 비용은 **증상이 원인을 안 가리킨다**는 것이다

CI 가 보여 준 것은 *"`CredentialJpaRepository` 쿼리 슬라이스 테스트 8칸 FAILED"* ·

**주석 한 줄**이 원인이라는 신호는 스택 4단계 아래 `PlaceholderReplacingReader` 뿐이다.
🔴 그리고 fan-platform E2E 는 **자기 프로젝트와 무관한** 이유로 빨개졌다(iam auth-service를
컨테이너로 띄운다) — 다음 사람은 fan 을 들여다볼 것이다.

## 🔴 로컬은 이것을 **구조적으로** 못 잡는다 (실측)

```
:auth-service:test  로컬 rc=0
  → CredentialJpaRepositoryTest   tests="8" skipped="8"
```

이 호스트(Windows + Docker 차단)에서 **Flyway 컨텍스트를 띄우는 칸은 전부 skip** 된다.
⇒ **로컬 초록은 마이그레이션을 한 번도 파싱하지 않은 초록**이다. 「다음엔 더 조심하기」는
처방이 아니다 — 조심할 수 있는 관측 자체가 로컬에 없다.

## 🔵 왜 `TASK-MONO-717` 은 가드를 안 만들었고, 왜 지금은 다른가

717 은 *"플레이스홀더는 Flyway 의 정당한 기능이므로 가드를 두지 않는다"* 로 판단했고

🔵 이 저장소의 규칙 그대로다 — **고쳐진 줄 알았던 면제는 두 번째 발생에서 회수한다.**

# Failure Scenarios

1. 🔴🔴 **가드의 메시지나 자기시험이 그 문법을 예시로 적는다** → 가드가 **자기 문서에 걸려**

3. 🔴 **한 서비스만 본다** → 다음 발생은 다른 프로젝트에서 나고 가드는 초록이다.

- [x] 🔴 **두 빨강은 내 변경과 무관하다는 것을 대조로 확인했다** — 손대지 않은 `main`
